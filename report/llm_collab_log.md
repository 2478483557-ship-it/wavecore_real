### 2026-10-23 #053 · 任务：新增数字锁相放大（测噪声底下的微弱信号）

- **我的提示词**：
  > "你提到的方向里有一个是物理上做不到的……（另一份建议：锁相放大 / 等效采样 / 量化对照）
  > 你给我做这个，我有时间改进，我唯一要做到的就是做的更好，而不是稳"

- **模型回答要点**：
  1. 先确认前提：**XC7A35T 无 GTP 收发器**（A75T 以上才有），PCIe / 光纤做不了，直接放弃。
  2. 选锁相放大：DDS 提供参考、ADC 提供信号、回环闭环，**现有模块拼起来正好是它**。
  3. 关键设计：参考 NCO 跑 25MHz 并取 **2×fcw**，与 50MHz 域的 DDS 严格同频；
     累加**整数个周期**（否则残留 2f 分量，读数会飘）。
  4. 复用 FFT 的旋转因子表做正交参考（1024×16 Q1.15），比 8 位正弦表精度高一个量级。
  5. **先写金标准模型**（`hw_analysis/lockin_model.py`），用真实 ROM 数据复现，
     在没上板前就证明算法对。

- **我的验证/自我纠错轨迹**（★ 上板连错四次，每次都不同性质）：
  1. **指令脉冲没在两处清零**：只在复位段加了 `lk_req <= 0`，
     每拍默认清零段没加 → 一次 0x9B 就让请求永久为 1，锁相帧无限重发，
     把测量行挤掉，所有读数变成解析乱码。**文件里早有同款注释（0x94 那次）。**
  2. **位宽写窄**：`lk_noise_w` 声明成 1 位、解码器输出 4 位。
     档位 8 = `1000b` 截断成 0 → 噪声永远不开，档位 2 同理，看起来"开不开一样"。
  3. **在 DAC 前插了寄存器**：`da_send` 是纯组合直连、DAC 在反相时钟锁存，
     插一级寄存器破坏建立关系 → **频率读数翻倍、Vpp 减半、TY 判成"其他"**。
     定位方法：把加锁相之前的源码原样重建烧进去，三个症状同时消失
     —— 这是唯一能停止怀疑 DDS 的证据。
  4. **有符号/无符号混算**：`sig1 + {{2{noise2[7]}}, noise2}` 里拼接是无符号的，
     整个加法按无符号算，负半周被零扩展成大正数撞上饱和，**正弦被削掉一半**。

- **结论**：上板实测（1000Hz，32 周期）
  ```
  衰减 噪声  真值mV  直接V   直接误差  锁相mV  锁相误差
   2    0    1200    1235    +3%      1200    0.0%
   2    8    1200    4287   +257%     1140   -5.0%
   3    8     596    3960   +564%      583   -2.1%   ← 直接测量差 6.6 倍，锁相差 2.1%
  ```
  资源：LUT 7469→7802（+333）、DSP 38→40、**BRAM 不变**（旋转因子表被合并）。

- **沉淀技能包**：**SK-075**（拼接是无符号的）


### 2026-10-23 #054 · 任务：观察带宽从 25kHz 做到 5MHz

- **我的提示词**：
  > "其实没必要做等效采样对吧，等效采样是针对高频信号的，我现在只要提高抽取就行呗……
  > 那你先把 t3t4 修了，然后尝试提高抽取力度，把 fft 和波形识别的范围直接扩大"

- **模型回答要点**：
  1. **纠正前提**：`timebase.v` 注释自己写着「decim 下限受 ADC 限制(25MSPS -> 最小 2)」，
     25kHz 是抽取选出来的，不是 ADC 上限。1~5MHz 根本不需要 ETS。
  2. 三个独立问题按顺序修：T3/T4 抓不到数据 → 频率换算 32 位乘法溢出 → 看门狗。
  3. 频率换算 `(bin * fs) >> 10` 在 Verilog 里结果位宽 = max(操作数位宽) = 32 位，
     fs=12.5MHz 时 511×fs = 6.4e9 必溢出 → 改成先撑成 42 位再乘（共 8 处）。

- **我的验证/自我纠错轨迹**：
  1. 上板实测四档：T1/T2 正常，**T3/T4 抓到平直数据**（不是"切档无响应"，是"采到空"）。
  2. **更严重**：切到 T3 后反复请求波形帧，**整块板子静默**，只能重新配置才恢复。
  3. 三次修复全部无效：① HOLD/FILL 加超时 ② 全状态看门狗+撤 req_l
     ③ 去掉 meas_busy/fft_busy 等待。**三次都失败反而说明不是状态机 bug，是设计耦合。**
  4. 根因：波形帧和频谱**共用同一个 decim**，对频谱够小的 decim 会饿死 1024 点环形缓冲。
  5. 处置：`wave_frame .decim_cfg(32'd1000)` **固定 50kHz，彻底不看 0x8D**。

- **结论**：频谱实测（自研 FFT 单峰）
  ```
  1 kHz   T1  999        100 kHz T3  99706
  1 MHz   T3  1000237    1 MHz   T4  1000261
  2 MHz   T4  2000474    5 MHz   T4  5000543（0.01%）
  ```
  时基往返后波形立刻恢复（3/3），板子全程存活。

- **沉淀技能包**：**SK-074**（带宽不够先怀疑抽取，别急着上 ETS）、
  **SK-076**（超时退出必须同时撤请求，否则是活锁）

### 2026-10-23 #056 · 任务：传感器前端要多大增益、要不要偏置（分析，未实施）

- **我的提示词**：
  > "我有震动传感器还有麦克风模块，然后你算算要多大增益，要不要偏置"

- **模型回答要点**：
  1. 量程换算：模块输入端 ±5V ↔ ADC 0~2V ↔ 0~255 码，**1 LSB = 36.33mV**。
     输入 0V = 码 128（正中），**输入 2.5V = 码 192**，只往上剩一半余量
     → **偏置到 2.5V 能用但浪费一半动态范围，信号应以 0V 为中心**。
  2. 目标峰值 3.5V（70% 量程），增益 G = 3.5V / 传感器输出峰值。
     MAX9814 说话 ~200mV → 17×；安静 ~50mV → 70×；801S 轻敲 ~20mV → 175×。
     **可调 3~200 覆盖全部。**
  3. **不要另加偏置，反而要隔掉传感器自带的直流**（MAX9814 输出 ~1.25V，
     放大 100 倍就饱和）。
  4. 带宽提醒：INA128 的 GBW 1.3MHz，单级 G=100 时只剩 13kHz，
     要 20kHz 音频需两级级联（10× × 10×）。
  5. **前置条件**：锁相必须有**同频激励**才成立。麦克风要有喇叭放 DDS 单音，
     振动要有振动源；否则只能做普通频谱分析。

- **结论**：方案可行，**本轮不实施**（用户决定先搁置）。数值已写入
  `report/sensor_frontend_guide.md`。

- **沉淀技能包**：否（属选型与电路计算，无新坑；但纠正了原文档"偏置 2.5V"的浪费）


### 2026-10-21 #052 · 任务：波形识别的真实频率上限，以及怎么把它做上去

- **我的提示词**：
  > "这个波形识别其实根本到不了 25k 正确率就已经不咋地了，你想想怎么改进"

- **模型回答要点**：
  1. 先别改代码，**先量**：扫频测出"错误从哪个频点开始"。
  2. 判据是 `|x-mid| > 3/8·span` 的样点占比，理想值方波 1.00 / 正弦 0.46 / 三角 0.25。
  3. 根因候选：固定降采样导致每周期样点数 `spp = 50000/F` 随频率下降。

- **我的验证/自我纠错轨迹**：
  1. **先上板扫频**（1k~25kHz × 三种波形），得到：
     1k/3k 全对，**5k 开始失效**，8k 时正弦被误判成三角，25k 全错。
     **对外声明写的是 25kHz —— 差了近一个数量级。**
  2. **先怀疑错了对象**：以为是 3 点中值滤波把正弦峰值削平。
     数值对比 5kHz 正弦：有中值 0.399 / 无中值 0.400，**差 0.001，推翻该假设**。
  3. 真正的证据在"扫相位取最坏情况"：
     ```
     spp = 8   → 正弦 0.25~0.50，三角 0.25~0.50   ← 区间完全重叠
     spp = 32  → 正弦 0.44~0.50，三角 0.25~0.26   ← 干净分离
     ```
     **spp=8 时两种波形采样下来在统计意义上无法区分**，不是精度差，是信息不足。
  4. 第一版实现（`decim ≈ 390625/F`，理论上可做到 200kHz）**实测打脸**：
     30kHz 以上全错，而且把抽取比从 32 提到 16（采样率翻倍、样点更多）**反而更差**。
     这说明限制不在统计方法，而在**信号本身**——板上 DDS 是 50MHz 台阶输出，
     采得越快台阶/毛刺占比越大。
  5. 于是把抽取比下限锁死 **32**，重测：1k~25kHz 三档全对且可重复。
  6. **顺带发现神经网络更差**（10kHz 以上全错）。查到训练脚本
     `f = uniform(15, 120)` 是"每周期样点数"而非频率，换算后网络只见过
     417Hz~3.3kHz 的特征分布。让特征提取共用同一个自适应抽取比后，
     **网络也做到了 25kHz**。

- **结论**：采纳。规则法与神经网络的上限均从 3kHz / 10kHz 提升到 25kHz；
  25kHz 以上主动报"其他"。代价 LUT +49、WNS +1.552 → +1.352 ns。

- **沉淀技能包**：**SK-072**（先量边界再改代码；采样率不是越高越好）


### 2026-10-20 #051 · 任务：Flash 固化一直失败，最后靠"证伪"而不是"猜对"

- **我的提示词**：
  > "ERROR: [Common 17-48] File not found: .../board_top.ltx 我这是固化失败了嘛"

- **模型回答要点**：
  1. `.ltx` 是 ILA 探针文件，`ILA_EN=0` 时本就不会生成 —— 先判断它是否致命。
  2. 检查 `.mcs` 是否存在、`program_flash.bat` 有无历史日志。
  3. 发现 `gen_mcs.tcl` 的 `-interface SPIx1` 与 XDC 的 `SPI_BUSWIDTH 4` 冲突。

- **我的验证/自我纠错轨迹**：
  1. `gen_mcs` 报 `[Writecfgmem 68-20]`，改成 SPIx4 后 `.mcs` 才第一次生成成功。
  2. `program_flash.tcl` 漏了 3 个 `PROGRAM.*` 参数，补齐后仍报 27-3347。
  3. **误判一**：把 `get_cfgmem_parts`（全软件列表）当成器件支持列表，
     改型号成 `qspi-x4-single` → 报"不支持 xc7a35t"。
     学会用 `-of_objects $dev` 才拿到本器件真正支持的型号。
  4. **误判二**：把 `.ltx` 报错当成固化失败根因，还写进了文档。
     后来做干净对照：先烧**确定没有 ILA** 的 bit，Vivado 明确报
     `no supported debug core(s)`，**固化依然失败** → **探针不是原因，撤回该结论**。
  5. **误判三（最该记的）**：用户操作期间我读到 0 字节，据此断言"Flash 是空的"。
     用户断电重启后板子照常出 `WIN=`，**证明 Flash 是好的** —— 空读什么都不能证明。
     这条错误在此之前已经犯过一次，是重复犯错。
  6. 排除清单最终包含 11 项（型号 / JTAG 频率 15M~1.5M / 参数 / 只读 blank check /
     cfgmem 残留 / refresh / mcs 容量 / FPGA 已配置 / 探针 / 端接 / -size 单位），
     仍未定位；改由 GUI 完成固化。

- **结论**：部分采纳。脚本 bug 修好了，但固化的根因**没有查明**，
  文档里如实写"未解决 + 已排除清单"，没有假装有结论。

- **沉淀技能包**：**SK-071**（从未跑过的自动化路径 = 未验证的路径）


### 2026-10-19 #050 · 任务：写针对性回归脚本，结果先抓出的是自己的错误
