# C1 · 通信四件事

## 1. 通信的本质
> 把一段"信息"（文字、数值、命令）从 A 点准确送到 B 点。
> 一共只有三样东西要解决：**①怎么把信息变成 01（编码）②01 怎么在线上跑（媒介）③B 怎么知道"何时读"（同步）**。

## 2. 信息 → 01（编码）
- 文字/数字先映射成整数：字符 A = 65；数值 1000 = 1000
- 整数再写成二进制：65 = 0100 0001（8 位）
- 在导线上用**电压**表示：高电平=1、低电平=0（我们板子 3.3V/0V）
- 接收方不追求"精确电压值"，只需**判决**：超过一半算 1、低于一半算 0（抗干扰的关键思想：宁粗不错）

## 3. 多位怎么送：并行 vs 串行（图②）
| | 并行 | 串行 |
|---|---|---|
| 线数 | 8 根同时发 8 位 | 1 根排队发 |
| 优点 | 快 | 线少、便宜、能拉长距离 |
| 缺点 | 线多、各位到得"快慢不一"（歪步）| 同样带宽需要更高时钟 |
- 我们系统：FPGA **内部并行**处理，出芯片时 **uart_tx 把 8 位变 1 位流**（串行化）；进来的位流由 **uart_rx 再拼回 8 位**（反串行化）

## 4. 何时读：同步 vs 异步（图③④）
**方案 A 同步**：多拉一根"时钟线 CLK"，A 敲一下 B 读一下——接线多、距离远不方便；SPI/I2C 用它
**方案 B 异步（串口用的）**：不加时钟线，靠两件事——
1. **事先约定节奏**：每位持续多久（波特率 460800 → 每位 2.17µs）
2. **发令枪**：发送方先发一个"起始信号"（拉低 1 位时间）；接收方看到它就开始"数拍子"
> 允许双方时钟有 ±5% 误差：因为一帧只有 10 位，误差累计不到半位就能读对（这就是"中点采样"的安全余量来源）

## 5. 帧：给位流画上"逗号"
异步没有"帧边界信号"，所以要用**固定格式打包**：`起始位 | 8 数据位 | (校验位) | 停止位`
- 起始位=拉开序幕；停止位=宣告结束（同时让线路回到高电平"休息"）
- 我们的 8N1：8 数据 + N 无校验 + 1 停止；线上 10 位/字节

## 6. 校验：怎么知道没读错（C4 细讲）
- UART 层可选"奇偶校验位"（弱，只能查单 bit 错）
- 应用层更强：`5A A5` 帧头 + `SUM` 字节（整帧求和，错一位整帧作废）

## C1 补充：层与层是"怎么隔开"的？—— 接口契约（2026-09-22）

**一句话：每一层只对外暴露"最小接口"，把细节藏在里面。**

### ① UART 层对外的"接口"（看 uart_tx 的端口定义）
```
uart_tx 的对外接口：
  输入: tx_data[7:0]（给一个字节）、tx_start（"发吧"脉冲）、clk、rst_n
  输出: tx_busy（"我忙着呢"）、txd（导线）
```
> 注意：这个接口里**根本没有"波特率"这个词**！波特率只是 UART 内部的一个参数：
> `uart_tx.v:12  parameter DIV = 108`（115200 用 434）。
> **换速度 = 只改这一个数字**（或在例化时 `#(.DIV(434))` 覆盖），外部接口一个都不动。

### ② 应用层看到的"接口"（cmd_decoder 的端口）
```
cmd_decoder 的对外接口：
  输入: rx_byte[7:0]（一个字节）、rx_done（"收到了"脉冲）
  输出: 各种命令脉冲（arb_load / sf_run / sweep_en ...）
```
> 它**永远看不到**位流、也看不到任何速率信息——只看到"一个个字节"。

### ③ 所以"改波特率要改什么"= 两张清单
| 层 | 要改吗 | 改什么 |
|---|---|---|
| 应用层（帧协议）| ❌ 不用 | 一个字都不动 |
| UART 层 | ✅ 要 | `DIV`：108（460800）↔ 434（115200）|
| 物理层 | ❌ 不用 | 线还是那根线 |
| **PC 端** | ✅ 要 | 串口助手里同样选 115200（**两端必须同步改！**）|

### ④ 真实故事（我们真的干过）
早期串口是 115200（DIV=434），波形帧要传 90ms；后来提速到 460800（只把 DIV 改成 108）——
**协议文档的帧格式一个字没改**，只是两端同时换了速度，帧长从 90ms 缩到 22ms。
> 这就是"层"的威力：**改动被关在了一个数字里**。

### ⑤ 可做的小实验（可逆，玩坏不了）
把 PC 串口助手的波特率**故意**从 460800 改成 230400 → 你会看到满屏乱码/收不到数据；
改回来就恢复。这证明："速度"完全是 UART 层的事，跟帧协议无关。

### ⑥ 为什么这很重要
- 分层 = **抽象**：把复杂系统切成"互不越界的几段"，每段只守好自己的接口
- 我们全队约定"**改协议先全队说+升版本**"，就是因为在**应用层**动刀会影响所有接收方；
  而在**UART 层**改速度只影响"两端同时改一下设置"
- 你以后学 TCP/IP、USB、CAN，全是这套思维——今天先把"两层"看顺，后面一马平川

## C1 学员理解核对（2026-09-22）——"包裹模型" v1 与修正

**学员原话**："内部每一个字符如 5A A5，两个为一组就是八位，协议层面并行加起始位截止位包好送进串行发送，是一个独立打包好的个体叫一帧；应用层把包裹符号拼起来看：前两个是 5A A5 就开始检查……"

**对的直觉（保留）**：
- "包裹"思维 ✓：发送＝打包，接收＝拆包
- "看开头两个是不是 5A A5，再按规矩检查" ✓：这就是接收状态机的核心动作
- "应用层管含义、底层管搬运" ✓：分层意识已经建立

**三处修正**：
| 原理解 | 修正 |
|---|---|
| "5A A5 两个为一组 = 八位" | ❌ **5A 是一个字节（8 位），A5 是另一个字节**；它们是**两个字节**，不是"两合一" |
| "一个独立个体叫一帧" | ❌ 单字节的 UART 包装叫**字符（10 位）**；**"一帧"= 一整条消息**（本例 10 个字节：2 头 + 类型 + 长度 + 负载 + SUM）|
| "协议层面并行打包" | ✅ 准确说法：**逐字节串行化**（每个字节→10 位，依次排队上线）；协议层看到的只是"字节的顺序" |

**两级打包（背下来）**：
1. **单字节级**（UART 层）：字节 → 1 起始 + 8 数据 + 1 停止 = 10 位
2. **消息级**（应用层）：多个字节 → 车头 5A A5 + TYPE + LEN + 负载 + SUM 验车员

**额外的关键点（学员问题引发）**：字节流没有天然边界，负载里理论上也可能出现"5A A5"——
这就是**必须有 SUM 的原因**：误同步的帧对不上校验，整帧丢弃，不执行。

## C1 结课：学员理解 v2 确认（2026-09-22）

**学员提问**："单字节包装再包装成一个完整的东西就成帧了，是不是？"

**回答：方向对，修正一个词——"不是再包一层壳，而是按规矩排成一组"**：
- 第 1 层（UART）：给**每个字节**穿"运输服"（起始/数据/停止=10位）—— 这一步是"包装"
- 第 2 层（应用）：**挑选若干个字节、按约定顺序排列**（5A A5 | TYPE | LEN | 负载 | SUM），再约定头尾标记 —— 这一步是"**编排/成组**"，帧本身不穿第二层壳
- 类比：每个箱子先贴好面单（可运输）；整批货按"车头-车厢-验车员"排成一列（成一帧）；**没有"把整列车再装进大箱子"这回事**
- 正因为没有物理外壳，接收方才要靠**逻辑标记**找边界：连续 5A A5 = 头；LEN = 数几节；SUM = 验货

✅ C1 通过！学员已能区分：字节包装（UART 层） vs 帧（应用层的编排规则）。

## ★ C1 结论卡（背诵版）
1. **通信三问题**：编码（怎么变 01）→ 媒介（并行还是串行）→ 同步（何时读）
2. **串行 + 异步 + 帧** = 串口（UART）；异步靠"约定节奏 + 起始位发令枪"，一帧 10 位内允许 ±5% 时钟误差
3. **两级打包**：UART 给"每个字节"穿运输服（10 位/字符）；应用层把"一串字节"按规矩排成帧（5A A5 | TYPE | LEN | 负载 | SUM）
4. **帧没有物理外壳**，靠逻辑标记找边界；负载万一同形"5A A5"，由 SUM 兜底丢弃
5. **分层靠接口契约**：外部只见"字节+脉冲"，速率藏在 `DIV` 参数里

## 波特率的精确说法（学员提问，2026-09-22）
问："能不能把波特率理解为每秒单字节包装速率？"
**答：接近，但不是。要拆成两个数：**
- **波特率（baud）本身 = 每秒传输多少个"位"**：460800 → 每秒 460,800 个位（每位 2.17µs）
- **每秒能传多少"字节"** = 波特率 ÷ 10（每字节被包装成 10 位）= **46,080 字节/秒**
> 所以：波特率像"车道限速（每秒多少个位）"；46,080 B/s 才是"每秒过几辆车（字节）"。
> 记住换算：**字节速率 = 波特率 ÷ 10**（8N1 才有这个"÷10"，因为有 2 个包装位）

# C2 · 电气与接线（慢速版）

## 1. 数字信号在导线上长什么样？
- **高电平** = 3.3V（本板 IO），**低电平** = 0V；这叫 **TTL 电平**（一种常见的电平标准）
- 接收方不看精确值，只看"高过一半 / 低过一半"（判决）
- 电平标准要对得上：3.3V 系统 ↔ 3.3V 系统最省心；5V 与 3.3V 混接有时要"电平转换"（我们板的 CH340 已处理好）

## 2. 为什么必须"共地"？（本课重点）
- 电压是**相对量**：说"3.3V"，必须回答"相对谁？"——相对 **GND**
- 两块设备如果**不共地**，各自的"0V 基准"可能相差几伏：
  → 接收方判决就会错、时好时坏、甚至坏芯片
- 所以串口连线是"三根一组"：**TX、RX、GND**；GND 是"同一把尺子"
- 现实坑：只接 TX/RX 忘接地 → "怎么时好时坏/随机乱码"的经典原因

## 3. TX/RX 为什么交叉接？
- TX = 嘴（发送），RX = 耳（接收）
- A 的 TX 要接 **B 的 RX**（嘴对耳）；接成 TX-TX 就是"两张嘴互相说，没人听"
- 调试提示：自环测试时把自己的 TX 与 RX 短接，可以"自己发自己收"

## 4. CH340 是干什么的？（翻译官）
- FPGA 只会说"高低电平"；电脑 USB 说的是"USB 协议"（D+/D- 差分线，协议复杂）
- **CH340 = 协议翻译官**：TTL 串口时序 ↔ USB 协议
- 电脑上看到"COM5"这种串口号，就是 CH340 在系统里注册出来的
- 我们链路：`FPGA(TX/RX/GND) → CH340 → USB → 电脑(COM 口)`

## 5. 常见错误速查（贴墙上）
| 现象 | 优先检查 |
|---|---|
| 完全收不到 | ①TX/RX 是不是交叉了 ②GND 接了没 ③两端波特率一致吗 |
| 时好时坏/随机乱码 | 共地不良、线材接触、旁边有强干扰 |
| 偶尔丢字 | 波特率误差偏大、线太长、或对端发送太快 |

## C2 答疑：波特率大 ≠ 发得频（2026-09-22，学员发现文档旧错误）
**问**："波特率 46 万，可我发数据的频率没那么高啊，是不是异步就是想发才发？"

**答**：两件事别混——**波特率是"线的通行能力"，发帧频率是"我们多久来一趟"**：
| 概念 | 数值 | 类比 |
|---|---|---|
| 波特率 460800 | 每秒能走 460,800 个**位** | 高速限速 120km/h（能力上限）|
| 一帧传输耗时 | 45B ≈ **0.98ms** | 一趟车实际开走的时间 |
| 出帧频率 | **≥10kHz 信号：~100 帧/秒（10ms 节拍）；低频（如1kHz）：~23 帧/秒（约43ms，含32周期测周窗）** | 我们"差不多每 10~43ms 发一趟车" |
→ 线在 90% 以上的时间是**闲着的**；余量专门留给"波形帧突发（1022B≈22ms）"和未来功能。

**"异步=有数据才发"**：✅ 完全正确！
- 空闲时线就是高电平"休息"；**帧与帧之间的间隔可以任意长**（毫秒、几小时都行）
- 但注意：**一帧之内，位与位必须连续按节拍走**（中间不能停）——所以才有"帧结构"来标记一头一尾

> 📌 本次讲课中发现旧文档把测量节拍写成"10Hz"，已按实测修正为 **~100Hz/~23Hz 两档**。
> 记住这一刻：**"读文档→发现不对→查代码→修正文档"**，这就是工程师的日常。

# C4 · 校验与容错（通信的"保险丝"）

## 1. 一个 bit 是怎么"翻"掉的？
| 死法 | 例子 |
|---|---|
| **噪声** | 旁边电机/电源跳动 → 线上电压瞬间被抬高/压低 → 判决成反的 |
| **时序** | 采样点漂移踩到位边界（C3 的预算被吃掉）→ 读错 |
| **瞬断/接触** | 接头氧化、插头松动 → 整段丢失或乱 |
| **对端状态** | 对方复位/重配置 → 流来源变了 |
> 这些**物理上防不完**（不可能买"绝对干净的线"）——所以通信的原则是：
> **不追求"不错"，而是"错了能发现"** → 用**冗余**来验货

## 2. 冗余的通用原理
发送前：算一个"指纹"，附在消息里；接收端：重算一遍比对 → 不一样就丢弃/重发。
不同的"指纹算法" = 不同的校验手段。

## 3. 奇偶校验（UART 层，可选）
- 做法：数一个字节里 1 的个数，补 1 位让它保持"偶数个 1"（偶校验）
- 能查：**奇数个** bit 翻转（1、3、5…个）
- 查不出：**偶数个** bit 翻转（2、4…个）——因为 1 的个数奇偶没变
- 局限：①能力弱 ②只能发现不能纠正
- 我们**没开它**（8N1 的 N）：省 10% 带宽，改用下面更强的

## 4. SUM 校验（应用层，我们实际用的）
- 做法：把 `5A A5` 之外的**所有字节求和，取低 8 位**，附在帧尾（例：0x85 帧的 `74`）
- 接收端重算比对：对不上 → 整帧丢弃、不执行
- 能查：绝大多数错误（含"2 个 bit 相抵"这类奇偶漏掉的）
- **理论盲区（碰撞）**：两个错误"恰好互相抵消"时总和不变（如 +1 与 −1 同时发生）
  → 概率极低，但对"高要求的行业"会用 **CRC** 替代（更强、也有代价：计算/功耗）
- 波形帧同款：1022 字节里 **1024 个样点全部参与累加**，比命令帧还严

## 5. 我们的"三层防线"（叠网思维）
| 层级 | 手段 | 拦什么 |
|---|---|---|
| 字符级 | UART 停止位检查（该高却低→本字符废）| 时序错、严重干扰 |
| 结构级 | `5A A5` 帧头 + `LEN` 长度一致 | 误同步、截断、错位 |
| 内容级 | `SUM` 求和 | 内容错误（绝大多数）|
> 已知一个理论盲区也别慌：**概率乘法**——"正确对齐"×"碰巧 SUM 还对"×"还撞上语义合理" 三者同时成立的概率极低。
> 这解释了上次的问题："假 5A A5"来了也会被后两道网拦掉 → 闭环 ✅

## C4 批改 + CRC 科普（2026-09-23）
**批改**：
- ①"同时反转奇偶不变" ✅（2 bit 翻转改变 1 的个数为 0 或 ±2，奇偶性不变 → 奇偶校验漏）
- ②"截断错位有 SUM 来弄" ⚠️ 半对：截断/错位**第一道网是结构级（5A A5 + LEN）**，SUM 是第二道兜底
- ③ 问"CRC 是什么" → 见下

**CRC 是什么（一分钟版）**：
- 把整段数据当作一个"大数"，**除以一个约定的除数**（二进制除法=异或+移位），**余数就是指纹**
- 除数叫"生成多项式"（工业标准有 CRC-8/16/32 等固定选择）；接收端重算，余数不一致即丢弃
- 为什么强：对**单 bit、双 bit、奇数个 bit、短突发错**都有**数学保证**（不是概率撞运气）
- 碰撞（不同数据算出同余数）≈ 1/2^k（k=校验位数）→ CRC-16 约 1/65536，CRC-32 约 1/4×10^9
- 代价：算法电路（移位寄存器 + 异或，几十 LUT）+ 帧尾多 1~4 字节
- 现实：以太网 CRC-32、Modbus CRC-16、SD 卡也有
- 我们暂不用的理由：帧短 + 环境误码低 + 三层防线已够；**列为可选升级项**（若做：CRC-8 起步最划算）

**费曼题（检错 vs 纠错）批改**：
学员观点："如果能纠错就能减少错误数据"——方向没错，但要补上**代价对比**：
- 纠错（FEC，如前向纠错/汉明码/RS 码）需要"更多冗余 + 更强算法"，成本高
- 而串口是**双向链路**：接收方发现错了，直接**要求重发**最便宜——所以工程普遍用"**检错 + 重传**"
- 只有"没有回程/来不及重传"的场景（卫星、光盘、深空通信）才用 FEC
- 补一句：我们的系统当前**没有自动重传**（命令丢了靠人工重发）；若要升级，可加 ACK/NAK 重传机制（选做项）

# C5 · 回到代码：状态机与 TX/RX 逐行

## 1. 状态机到底是什么？
> **"现在在哪一步（状态）+ 什么条件能走（门票）+ 走的时候顺便干什么（动作）"**
像自动售货机：待机 →（投币）→ 选货 →（按按钮）→ 出货 → 找零 → 回到待机。
模板骨架（我们所有模块都一样）：
```verilog
always @(posedge clk or negedge rst_n)
    if (!rst_n) st <= IDLE;            // 复位：回到起点
    else case (st)
        IDLE: if (门票) begin 动作; st <= 下一步; end
        ...
    endcase
```
> "时序"的含义：他只在**每拍的时钟沿**做判断/搬家——所以速度=拍子（20ns/拍）。

## 2. 对着 uart_tx 逐行走（对应状态机图上半）
| 代码行 | 在图上的意思 |
|---|---|
| `uart_tx.v:41` S_IDLE: `txd<=1` | 空闲必须高（线上休息）|
| `:43-47` if(tx_start) → busy=1, 进 START | 门票=tx_start 脉冲 |
| `:50-56` S_START: `txd<=0`；数满 DIV 拍 → DATA | 起始位=拉低 1 位时间 |
| `:59-67` S_DATA: `txd<=tx_data[bit_cnt]`；每 DIV 拍 `bit_cnt++` | 低位先出，8 位 |
| `:70-75` S_STOP: `txd<=1`；数满 DIV 拍 → IDLE | 停止位，回到空闲 |
细节三条：
1. `txd <= tx_data[bit_cnt]` 是**每拍都执行**的——值不变也写，保证信号稳定
2. `cnt` 是"每位的秒表"（数到 DIV-1 归零）；`bit_cnt` 是"第几位"
3. 全程 `tx_busy=1`，让上层知道"别插队"——让路机制的源头

## 3. 对着 uart_rx 逐行走（图下半）
| 代码行 | 意思 |
|---|---|
| `:47` S_IDLE: `if(!rxd)` | 抓到下降沿（起始）|
| `:54-57` S_HALF: 数 **HALF=54 拍**到起点中点，**复查 !rxd** | 复查=毛刺删除术：抖一下不算数是真起始 |
| `:63-67` S_DATA: 每 **DIV=108 拍**采 1 位 `rx_data[bit_i]` | 每位中点采样（C3 的数学）|
| `:72-75` S_STOP: 数满 DIV 拍 → `rx_done<=1` 回 IDLE | 单拍脉冲通知上层 |

**"什么时候用脉冲、什么时候用电平"速记**：
- **事件/动作**（收到一个字节、完成一次计算）→ **脉冲**
- **状态/条件**（正在发送、处于扫频模式）→ **电平**

## 3. 一次 0x85 的完整因果链（背下来，答辩超好用）
```

→ sine_rom 查表值每拍变化 → da_send 打给 DA → 模拟波形出现 1kHz
→ 回环到 AD → ad_cap → freq_meter 数周期 → 测量行 F=0001000……
→ 你串口里看到 "F=0001000Hz" —— 闭环完成！
```

## 4. 上行：让路机制（对应本页图）
- 四路'说话人'：波形帧(①) 谱峰行(②) 自研FFT(③) 测量行(④)
- 仲裁规则：**波形 > 谱峰 > 自研FFT > 测量**（一行 `assign` 三态选择器）
- `ext_hold`：①或③在发时，给测量模块"忍住"信号 → 防止把测量行"腰斩"
- 若没有它：会出现 `F=0001S=0001001` 这种被拦腰截断的混合行（乱码）——让路机制解决的就是这个

## 5. 单写者规则（一句话复述 SK-021）
- `wr_idx`（写指针）**只能由采集块写**；状态机要归零 → 发 `fill_rst` **脉冲**，不直接动手
- 这叫"**控制与数据分离**"：谁拥有数据，谁独家写；别人只能"请求"
