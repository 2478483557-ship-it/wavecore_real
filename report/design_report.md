## 1. 选题背景与创新点

### 1.1 背景与问题
"口袋仪器"（信号源+测量+频谱一体）在实验教学、嵌入式调试与现场检测中有明确需求：传统方案要么靠昂贵台式仪器，要么用 MCU 方案牺牲实时性与精度。FPGA 的并行性、确定性时延与可重构能力，恰好匹配"多参数并行测量 + 频谱分析 + 实时触发"的任务形态。

我们对同类公开作品做了对标（`report/benchmark.md`）：官方命题类赛题竞争集中；而"完整测量链路 + 频谱"方向公开作品较少，**多为一机单功能**（或仅有频谱、或仅有信号源）。本项目选择"一机集成"路线，并在工程完备度上做深。

### 1.2 主要创新点
1. **一机集成"四台仪器"**：信号源、全参数测量、频谱分析、波形采集与触发，在同一颗 35T 上并行共跑；
2. **"同板双 FFT"对比**：厂商 4096 点 IP 与手写 1024 点 Radix-2 DIF FFT 同板并存，资源与精度同口径对比（自研核 502 LUT / 7 DSP，约为 IP 裸核的 1/3 资源；读数与 Python 金标准逐字一致）；
3. **测量鲁棒性设计**：四层数字抗噪（2 拍确认 / 施密特迟滞 / 5 点中值 / 3 窗中值）+ **可信闸门**（测不准时输出"其他"而非错误结论）；
4. **工程方法论沉淀**：以"数据 → 假设 → 错误变体仿真 → 上板复现"的闭环定位根因，全过程沉淀 **35 条可复用技能包**。

## 2. 设计原理与功能框图

### 2.1 系统框图
【图 1 位置：系统框图（可用 `report/learning_notes.md` L0 数据流图重绘）】

数据流一句话：命令 → 解析 → DDS 查表 → DA → （回环/外部信号）→ AD 采样 → 并行四路处理（测量 / FFT / 波形缓存 / 识别）→ 串口多路让路上报 → PC 上位机。

### 2.2 模块清单（19 个 PL 模块，源码见 `src/`）
| 功能域 | 模块 | 说明 |
|---|---|---|
| 顶层与协议 | board_top / cmd_decoder / uart_tx / uart_rx / uart_mirror | 例化、帧解析（5A A5 头 + SUM 校验）、460800 收发、转发口（备用） |
| 信号源 | freq_ctrl / dds_nco / sine_rom / dds_top / dual_tone / key_debounce | 档位与任意频仲裁、32 位相位累加、256 点查表、双音合成 |
| 模拟接口 | da_send / ad_driver | DA 并口推送 / AD 采集（50kHz 有效采样流） |
| 测量 | freq_meter / measure_report | 闸门法/测周法、占空比/脉宽/Vpp、四层抗噪；F/D/W/TY 上报 |
| 频谱 | fft_demo / fft_report / hann_rom / self_fft_1024 / self_fft_report / twiddle_rom | 4096 点 IP 链与自研 1024 点链；S/A 与 SF/S2/S3 上报 |
| 采集与识别 | wave_frame / wave_id / sweep_ctrl / bin2bcd / div_restore | 触发采集、波形识别、扫频、显示转换辅助 |

### 2.3 关键原理（摘要）
- **DDS**：`f_out = fcw × 50MHz / 2^32`；查表取相位高 8 位（相位截断）。
- **测频**：高频用 10ms 闸门数周期（`f=N×100`）；低频切换测周法（数 32 个周期的时钟拍，`f=32×50MHz/N`），误差互补。
- **频谱**：帧截断加 **Hann 窗**抑制泄漏；FFT 蝶形 `O1=A+B, O2=(A−B)×W`，1024 点 = 10 级 × 512 只 = 5120 只蝴蝶（较朴素 DFT 快约 205 倍）。
- **触发**：检测边沿（对比上一拍电平）→ 指针归零 → 写满 1024 点，保证"帧首点=触发点"。
- **识别**：统计"近极端（>0.75 幅度）时间占比"：方波≈100% / 正弦≈46% / 三角=25%（比较器+计数器实现，零乘法）。

## 3. 软硬件划分依据与接口设计

### 3.1 划分依据
- **PL（FPGA）承担实时链路**：采样、测量、FFT、触发、识别、协议——任务并行且对时延确定性敏感（20ns 时间刻度）；
- **PC 上位机承担可视化**：波形显示、仪表板、频谱瀑布图（Spectrogram）——数据经 460800 串口直连；
- **预留 F1 转发口**：供 STM32 等外设镜像串口流（本阶段不启用）。
- 说明：本项目**不使用 PS/软核**，全部功能由 PL 逻辑实现——这是初级组"考察基本 FPGA 设计能力"定位下的主动选择。

### 3.2 接口设计（自定义帧协议 v1.17，全文见 `board/uart_protocol.md`）
- 帧格式：`5A A5 | TYPE | LEN_H LEN_L | PAYLOAD | SUM`（SUM=除帧头外全部字节求和取低 8 位）
- 下行命令（19 条）：0x81 档位 / 0x85 任意频率 / 0x87 双音 / 0x88 波形 / 0x89 触发 / 0x83 抓波 / 0x8A 自研FFT / 0x8B 扫频……
- 上行行：`F=`／`D=W=`／`TY=`／`S=A=`／`SF=S2=S3=`／波形帧（1022B）
- 物理层：AD/DA 模块（AD9280/AD9708）并口；IO 电平按 Bank 约束（见 `src/wavecore.xdc` 与 `board/pin_map.md`）

## 4. 优化过程与前后对比

### 4.1 资源优化（关键四轮）
| 阶段 | 问题 | 措施 | 结果 |
|---|---|---|---|
| 1 | FDRE 超限（77,108 > 65,950）| 大缓存改 **Block RAM**（`ram_style` + 读写分离）| 综合通过 |
| 2 | LUT 超限（21,775 > 20,800）| 窗函数表改 **`$readmemh` 块 ROM** | LUT 降至 19,282 |
| 3 | 波形缓存推断不稳 | 全部大存储改用 **官方 IP（BMG）** | 一次通过（SK-016） |
| **4** | **实现阶段 LUT 超容（`opt_design` 后 20,829 > 20,800，只超 29 个，`place_design` 报 `[DRC UTLZ-1]` 中止）** | **定位到 `fft_demo.v` 的 `f_ram`（4096×8）从未进块 RAM —— 读口的异步复位让 Vivado 放弃推断，退化成 32,768 个 FDRE + 4096:1 读 mux，独占全设计 86% LUT / 93% FF。改用教科书 SDP 模板（读口去异步复位、读写口各自独立 `always`、地址截位）** | **LUT 20,829 → 5,117（−75.4%）；Reg 35,818 → 4,834；F7/F8 Muxes 4379/2180 → 21/4；0 布线错误，WNS 反升至 +1.689ns（当日再改 `GAP` 消假峰后重建的最终值）。详见 `report/lut_slim_report.md`（SK-029）** |

> 第 4 轮的方法论要点：**不能只看资源总数，要回头核对"我改的那一个东西真的变了吗"**。
> 阶段 2 曾"顺手"把总数降下来，却掩盖了 `f_ram` 从未进 BRAM 的事实，藏了 25 天。
> 本轮的闭环证据是**原语类型**：`u_fft_demo/f_ram_reg` 由 `FDRE` 变为 `RAMB36E1`。

### 4.2 自研 FFT 与厂商 IP 同口径对比
| 维度 | 自研 Radix-2 DIF | xfft IP | 说明 |
|---|---|---|---|
| 点数 | 1024 | 4096 | 同口径按"每点资源"归一 |
| LUT / FF | **502 / 346** | 1771 / 2550 | 自研约为 IP 的 1/3 |
| DSP | **7** | 9 | 串行复用 vs 流水线 |
| 结构 | 迭代式（512×10 只蝴蝶，串行） | radix-4 burst IO 流水 | 面积换速度 |
| 运算耗时 | ≈0.92ms/帧 | 快得多 | 采集窗 20.5ms 为全链主导项 |
| 数据一致性 | **正弦 SF/S2/S3=976/0/0；方波 976/2978/4980 Hz**（基波/3 次/5 次谐波） | S=1001 精确 | 详见 `report/resource_compare.md` |

### 4.3 通信带宽优化
| 版本 | 波特率 | 波形帧耗时 |
|---|---|---|
| 早期 | 115200 | ≈90ms |
| 现行 | **460800** | **≈22ms**（协议帧格式不变，仅两端改速率）|

### 4.4 抗噪优化（四层，详见 `report/denoise_experiments.md`）
| 层 | 手段 | 修前 → 修后 |
|---|---|---|
| 1 | 穿越+重武装"连续 2 拍确认" | 正弦 ×2/乱跳 → F 精确 |
| 2 | 占空比"施密特迟滞" | D 被切碎 → 稳定 |
| 3 | 5 点中值滤波 | V 201 → 140（与 PC 抓图一致）|
| 4 | 3 窗中值（D/W/V）| 偶发坏窗（D 掉 047）→ 稳 050.x |

> 定位说明：本项目为"LLM 深度参与工程"的实践样本。协作边界明确：**人负责需求定义、方案选择、上板验证与最终判断；模型负责起草、变体仿真、审查与文档生成**。

### 5.1 工作流
现象/需求 → 与模型协作产出方案或代码 → **人上板实测** → 数据对照 → 若不符，进入"错误变体"复现式定位 → 修复 → 回写技能包。

### 5.2 三类典型协作（含自我纠错轨迹）
1. **"复现硬件式排障"（SK-025）**
   - 现象：自研 FFT 读数稳定但错误（1kHz → 1367Hz）
   - 轨迹：模型提出"读地址晚一拍/晚两拍"两种错误变体并仿真 → 变体恰在两组频率上逐字复现硬件输出（[1367,1318,1709]/[2686,3369,8740]）→ 锁定 BRAM 2 拍读延迟 → 修复找峰等待逻辑
2. **"工程语义陷阱"（SK-023）**
   - 现象：状态机"从未前进"（采集正常）
   - 轨迹：人工直觉怀疑"卡死"，模型按 Verilog 语义构建"default 覆盖赋值"变体 → 复现 → 修复（补空 case）
3. **"设计文档与代码一致性审查"（多次）**
   - 轨迹：模型全库审计发现"技能包清单缺失后 12 条""重复条目""陈旧状态未更新"等 → 当场修复
   - 价值：把"文档漂移"这类人易忽略的问题交给模型批量扫描

## 7. 复现说明

### 7.1 硬件清单
- 正点原子达芬奇Pro（XC7A35T-2FGG484）x1；高速 AD/DA 模块（AD9280 + AD9708）x1；USB 线；回环线（DA→AD）
- 可选：USB 转串口（板载 CH340 即可）；无需示波器亦可完成全部自测（回环+PC 交叉验证）

### 7.2 从零复现步骤（约 20 分钟）
```
1) git clone <repo>            # 纯英文目录结构
2) Vivado 2020.2 打开 → Tcl Console:
   source build/create_project.tcl     # 自动建工程+重建IP+重写hex路径
3) Run Synthesis → Implementation → Generate Bitstream
   预期资源（实现后）：LUT≈24.6%、FF≈11.6%、DSP=27、BRAM Tile=10；WNS>0
4) Program Device（或按 board/flash_guide.md 固化到 Flash）
5) 打开任意串口工具（460800-8N1）→ 观察 F=/D=W=/TY= 数据流
6) 按 board/uart_protocol.md §6 帧速查表发送命令（波形/频率/抓波/自研FFT/扫频）
7) 可选：运行 host/ 上位机脚本查看波形与测量
```
### 7.3 预期结果对照（与本文档数字一致）
- 1kHz 方波：`F=0001000Hz D=049.9~050.4% W=00005xx us TY=0`
- 1kHz 方波 + 0x8A：`SF=0000976 / S2=0002978 / S3=0004980`（bin20/61/102，±1 bin）
- 1kHz 正弦 + 0x8A：`SF=0000976 / S2=0000000 / S3=0000000`
  （正弦的 S2/S3 必须为 0；**非 0 说明板子上跑的还是修复前的旧固件**）
- 温度提示：正弦绝对占空比受模拟链路温漂影响（冷机≈50% → 热机≈46.8%），**测量基准请用方波**；详见 8.1

### 7.4 工具版本说明（官方要求非推荐版本的解释）
本工程使用 **Vivado 2020.2**（官方推荐 2026.1/2025.2）：
1. 达芬奇Pro 官方资料与例程基于 2020 系列，新手学习成本最低；
2. Artix-7 在 2020.2 支持完备，功能实现无差异；
3. **提供 `build/create_project.tcl` 保证脚本级可复现**，版本不影响他人复现核心流程；
4. 后期将评估新版兼容性并补充对比说明（如兼容则升级）。

## 8. 失败分析（诚实边界）

### 8.1 已知边界与解释
| 现象 | 原因 | 处理 |
|---|---|---|
| 正弦占空比 46.8~49.6%（随温度）| 模拟链路热平衡温漂（案例见 `report/engineering_challenges.md` 7.5）| 预热 3 分钟；方波为计量基准；终验用外部信号源 |
| >25kHz 频谱混叠 | 采样率 50kHz 设计使然 | TY 闸门报"其他"；多档 fs 列为可选扩展 |
| 自研 FFT 为迭代式（0.92ms/帧）| 面积换速度的主动取舍 | 采集窗 20.5ms 主导，按需运行足够 |

### 8.2 未完成/未实施（及原因）
- 音乐彩蛋（麦克风链路）：需额外硬件与资源（**资源攻坚前**主设计 LUT 占用 95.5%，
  现已降至 24.6%，资源不再是阻碍，但需额外麦克风硬件），列为可选；
- 高频段多档采样率、CRC 校验、自动重传：均在 `report/backlog.md` 记录，为"排期未做"而非"未知"。

### 8.3 若重做一遍会改进什么
