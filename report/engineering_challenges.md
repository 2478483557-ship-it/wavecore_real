# 工程问题与解决（报告章节初稿）

> 用途：作品报告"工程问题与解决"章节 + 答辩讲述素材
> 日期：2026-09-20 ｜ 素材来源：SK-017/019/021/022/023/024/025/026 与对应实测日志

## 0. 方法论：我们如何定位"玄学"问题

本项目的排障统一遵循一条闭环，全部案例均以此收口：

```
现象（数据） → 提出可证伪假设 → Python 建模（含"错误变体"）→ 预测硬件表现
             → 上板实测对照 → 变体命中即根因 → 修复 → 回归验证
```

其中最有力的一招是 **"复现硬件式仿真"**：把硬件给出的"错误数字"当作假设变体逐个建模，谁能逐字复现实测数据，谁就是真凶（案例 4/6 均一击命中）。

## 1. 占空比/脉宽：从"半周期近似"到"计窗统计"（SK-017）

- **现象**：最初用"最长高电平/半周期"估算占空比，方波 1kHz 下读数在 45%~55% 抖动
- **根因**：测量窗口与信号不同步；单周期计数受毛刺与相位影响
- **解决**：改为 **计窗统计法**——固定窗口（1kHz 档 32ms/16M 拍）内统计高电平样本占比，窗口起点与结束原子化；判高带 4 LSB 迟滞
- **验证**：方波 1kHz D=49.7~49.9%（理论 50.0%）、1MHz D≈50%，W=499~500µs

## 2. 正弦频率 ×2 / 乱跳："假穿越"与三层数字抗噪（SK-019）

- **现象**：正弦（尤其 ≥2kHz）频率读数近似翻倍（1k→~2k）或乱跳（曾达 5 万+）；同频方波完全正常
- **定位**：板子 50MHz 全速可见"波形上的快速毛刺"（占空比 35% vs 电脑抓图 51% 的矛盾），毛刺让迟滞阈值多触发"假过零"
- **解决（三层）**：
  1. 阈值穿越 + 重新武装 **均需"连续 2 拍确认"**（治 ×2）
  2. 占空比统计判高改 **施密特迟滞**（防毛刺切碎时段）
  3. 测量路径 **5 点中值滤波**（9 比较器排序网络，Python 20 万组验证；清 ≥2 拍尖刺）
- **验证**：正弦 1k/100k：F 精确、D=49.6~50.0%、W=500µs/6µs、V=140（与电脑抓图 139 一致）；方波指标不降

## 3. 触发采集语义：环形缓存必须"单写者归零"（SK-021）

- **现象**：触发采到的波形"起点不对齐"——上升沿触发时帧首并非边沿
- **两个坑**：
  1. **语义坑**：直接读环形缓存得到的是"触发前历史"；须在触发瞬间**写指针归零**，再写满一整圈
  2. **DRC 坑**：状态机直接写 `wr_idx` 与采集块冲突（multi-driven net）；改为**单写者 + 控制脉冲**（`fill_rst` 一拍），指针始终由采集块独家修改
- **验证**：方波 1kHz，上升沿触发帧前 6 点全高、下降沿全低（前/后 6 点判据，PC 独立审计）

## 4. 自研 FFT 的"从未前进"：case-default 吞掉非阻塞赋值（SK-023）

- **现象**：0x8A 触发后核心**永远不出结果**；探针显示采集正常（写指针 4→7 爬满 1024），但状态机纹丝不动
- **定位**：采集结束分支写 `st<=S_START`，同拍 `case(st)` 因**缺少 S_CAP 项走了 default** `st<=S_CAP`——同一 always 块内对 st 的两次非阻塞赋值，**后者胜**，状态被悄悄拉回
- **修复**：给 S_CAP 加显式空 case
- **经验**：仿真按"理想语义"手写会通过（我们最初的 FSM 仿真就通过了），**必须按 Verilog 真实语义（同周期 last-write-wins）建模**
- **验证**：修复后核心全流程 21.5ms 完成，SF 行首次输出

## 5. 二峰检测"明明有峰却不出"：单趟流式双峰的三个连环坑（SK-022）

- **现象**：方波输入时 FFT 第二峰（3 次谐波）永远不显示；双音却正常
- **三层根因（逐个击破）**：
  1. 候选判定用"当前主峰"排除近邻，而**主峰寄存器更新晚一拍** → 主峰自己被存为候选
  2. **Hann 旁瓣（±1 bin，幅度约 50%）**会顶掉真正的次峰（方波 3 次谐波仅 33%）
  3. 正解：**"降级"与"候选"双端都加"相隔>2 bin"约束**的双最大值级联
- **验证**：方波 1kHz → S=1001 + **A=3003**（3 次谐波）稳定；`report/resource_compare.md` 有配对数据

## 6. 自研 FFT 数值"稳定但错"：表错骗过仿真 + 镜像抢峰（SK-024）

- **现象**：硬件读出 1367Hz（应≈976Hz），且每次一样（"稳定错"）
- **根因 A**：旋转因子表生成脚本误在每个值后补 0（`[c0,0,c1,0,...]`），半数地址为零；而 Python 金标准用 `math.cos()` **直算没走表** → 仿真全绿、硬件全错。**教训：金标准必须从同一份 hex 读表**
- **根因 B**：实数谱 ±f 双峰等幅，找峰未限"正半轴"时会选中 1024−bin 的镜像
- **验证**：修表 + 限定 `rev10(i)≤511` 后，走表金标准与硬件均为 bin20（SF=976）

## 7. 收官一击：BRAM 2 拍读延迟与"统计窗口采样率"（SK-025 / SK-026）

- **现象 A（SK-025）**：数值修复后 SF 仍为 1367（bin28）；"读 i−1"假设的变体仿真**在 1kHz/2kHz 两组数据上逐字复现硬件输出**（[1367,1318,1709]/[2686,3369,8740]）→ 根因：`blk_mem_gen_1` 为 **2 拍读延迟**；蝶形读加了等待、**找峰扫描漏加** → 全部读到前一地址。修复：找峰同样加一拍等待（地址保持期间数据有效，对 1/2 拍延迟均安全）
- **现象 B（SK-026）**：波形识别"怎么调都是 3"；根因：设计窗口是"2048 点@50kHz≈41ms"，代码却**逐时钟取样**（41µs）→ 1kHz 连零头都不到。修复：模块内置 50kHz 降采样节拍
- **验证**：自研 FFT（1kHz 方波）SF/S2/S3 = 976/2978/4980 Hz（基波 bin20 / 3 次 bin61 / 5 次 bin102）与 Python 金标准逐字一致（9/28 修复偏移二进制映射 bug 前的旧读数为 976/1025/2978）；**注：仿真用整周期激励落在 bin60/bin100 → 2929/4882，那是仿真的 bin，板子跑 1000Hz 是 bin20.48 所以偏 1~2 bin。**波形识别五场景（正弦/方波/三角/混叠/双音）TY=1/0/2/3/3 全对
  > ⚠️ **该条已被 2026-09-28 的案例 8 修正**：S2=1025 是同一主瓣内的相邻 bin（假峰），
  > 且当时的"逐字命中"是在**错误的输入映射**上取得的（只测了方波，而方波恰好躲过该 bug）。以案例 8 为准。

## 7.5 案例补充：正弦占空比的"温漂"（2026-09-20 观察）

- **现象**：1kHz 正弦回环，**冷机上电 D≈50.0%（V≈140）→ 热机几分钟后 D≈46.8%（V≈153）**，之后长期稳定；同环境下方波全程 50%（不受影响）
  （注：此处 `V≈140/153` 是当时 LSB 口径；v1.17 起 `V=` 改 mV，140 LSB ≈ 1094 mV）
- **排查**：git 证实生成/测量代码无实质变更（仅 1 拍流水延迟）；方波指标不降；D 与 V 同步漂移
- **结论**：**模拟链路温漂**——DA/AD 模块偏置网络/运放/基准的热平衡过程造成小幅（~4-5 LSB 级）波形不对称；正弦的"过中占比"对这一级别的不对称高度敏感（≈0.2dB 不对称即可引起 ~3% 偏移），方波天然免疫
- **后续加固（窗口级）**：观察中发现另有"**偶发坏窗**"（约每几秒一次）：V 135↔151 闪烁、紧随其后 D 掉至 047（1 个窗口被宽毛刺污染 max/min，中线随之偏移）→ 加入**"最近 3 窗中值"输出平滑（D/W/V）**，坏窗被投票否决；修后 100kHz 方波 V 恒定、D=049.9~050.4 稳定
- **工程处理**：①文档化（本案例）②演示/测量前**预热 3 分钟**或采用方波基准 ③终验用外部信号源（11 月）④三级降噪补齐（样点级→事件级→窗口级）
- **价值**：这是"真实模拟世界"的教科书现象——比读数本身更能体现对测量链路的理解深度

## 8. 自研 FFT"方波对、正弦错"：把偏移二进制当成补码用（2026-09-28，收官发现）

- **起疑点**：三峰回归仿真里，**1kHz 方波和 1kHz 正弦跑出逐字相同的 976/2929/4882**。
  两个物理上完全不同的信号不可能有完全相同的频谱——要么"被测信号根本没进去"，要么"输入被改形了"。
- **定位**：`self_fft_1024.v` 采集行写的是 `din <= {ad_cap, 24'd0}`，
  而蝶形与找峰**全程按有符号（补码）**读 `dout[31:16]`。
  AD9280 输出的是**偏移二进制**（中点 128），于是这句等价于"把 ad_cap 当有符号 8 位用"：

  | ad_cap（原始码） | 想表达的值 | 旧写法读回来 | 后果 |
  |---|---|---|---|
  | 128（中点） | 0 | **−32768** | 满量程负 ⇒ 直流分量巨大 |
  | 228 | +100 | −7168 | 跨过 128 处出现**断崖** |
  | 28 | −100 | +7168 | — |

  ⇒ 一个 29~227 的**正弦被断崖劈成锯齿**，**凭空造出 3 次/5 次谐波**；
  而方波是 28/228，正好映射成 ±28，**不跨断崖**，所以方波看起来一直"是对的"。
- **为什么之前没发现（最值得写进报告的一点）**：SK-024 那轮验证**只用了方波**。
  方波恰好躲过这个 bug，于是"数值与模型逐字一致"这个结论，
  是**在一个错误的输入映射上**取得的。
- **修复**：`din <= {(ad_cap ^ 8'h80), 24'd0};`
  异或 0x80 等价于减 128（mod 256），即"偏移二进制 → 补码"，把中点归零：
  `128→0`、`228→+100`、`28→−100`（且 `+100×256 = 25600` 不溢出 16 位有符号）。
- **对照**：IP 通路 `fft_demo.v` 一直是 `$signed({8'd0,m_q}) - 16'sd128`，**本来就是对的**。
  也就是说两条 FFT 通路对同一个 ADC 字节的解释曾经不一致——这正是"两条通路边跑边对照"的价值。
- **附带加固**：找峰扫描显式**跳过 bin0（直流）**。直流不是频率分量，排除是标准做法，
  也防止残余偏置把 SF 顶成 0Hz。
- **验证**：`sim/fft_check/` **五场景**回归（`bash sim/fft_check/run_fft_check.sh`）——
  方波 / 正弦 / 双音2bin / 双音80bin / **非整数 bin（20.5 周期）**，
  最后一条是"板上假峰"案的回归项（加 Hann 窗前它会报 `S2=1171`）

  | 场景 | 期望 SF / S2 / S3 | 实测 | 结论 |
  |---|---|---|---|
  | A 方波 20 周期 | 976 / 2929 / 4882 | 976 / 2929 / 4882 | ✅ 逐字一致（3、5 次谐波）|
  | B **正弦 20 周期** | 976 / **0** / **0** | 976 / 0 / 0 | ✅ **修复前是 976/2929/4882**，假峰被清除 |
  | C 双音 相距 2 bin | ≈976 / 0 / 0 | 976 / 0 / 0 | ✅ 物理上分不开，诚实报单峰 |
  | D 双音 相距 80 bin | 976 / 4882 / 0 | 976 / 4882 / 0 | ✅ 确有真双峰时仍能分开 |

- **教训（答辩可直接讲）**：**"仿真通过"只在"激励和现场一样"时才等于"硬件正确"。**
  这里只需要把激励从方波换成正弦，bug 就暴露了；而它在方波下可以一路绿灯走到答辩现场。
  我们的对策是把"换波形类型"变成回归用例的固定一项。

## ★ 证据金句（可直接写进报告 / 答辩引用）

> 下面两句不是形容词，是两条**有独立数据支撑**的事实陈述。建议原样引用，
> 因为它们各自回答了评委最可能问的一句："你凭什么说你的抗噪是真的有效？"

### 金句一 · 抗噪有效性的"自然实验"

> **同一路 1kHz 方波、同一块板卡，只把触发极性从上升沿换成下降沿，
> 上位机按原始波形算出的 Vpp 就从 111 LSB 跳到 184 LSB（差 66%）；
> 而 FPGA 内部报告的 Vpp 两次都是 111 LSB。**
> **也就是说：差异不是来自测量，而是来自"原始数据里的边沿振铃"——
> 三层数字抗噪把它挡在了测量之外。**

**数据出处**：`report/host_gui_review_2026-09-27.md`

| 抓包号 | 触发 | 原始 min/max | 原始波形 Vpp | FPGA 测量 Vpp |
|---|---|---|---|---|
| 180048 | 下降沿 | 68 / 252 | **184 LSB** | **111 LSB** |
| 180012 | 上升沿 | 69 / 180 | **111 LSB** | **111 LSB** |

**为什么这句有说服力**：这是一个"**只改一个变量**"的对照实验（只换触发极性），
所以"原始数据变了、测量值没变"只能归因于抗噪环节，而不是归因于信号本身变了。
它同时解释了上位机上"波形图脚注 Vpp"与"面板测量 Vpp"不一致的疑问——
**两者本来就该不一样：一个是原始数据，一个是抗噪后的测量结果。**

### 金句二 · 第三方（PC 侧 CSV）独立复算

> **对上传的 1024 点原始波形做逐点独立审计：帧校验正确、1024 点连续无缺失、
> 正常低/高电平稳定在 ≈70 / 179 LSB；
> 全部 10 个异常点都是"单点、20µs（恰好 1 个采样周期）、且全部出现在电平切换处"，
> 最大 252 LSB。**

**为什么这句有说服力**：它把"噪声是什么形状"量化出来了——
**时宽只有 1 个采样点（20µs）、位置只在跳变沿**。
而本项目测量路径的 5 点中值滤波，设计目标正是"清除 ≤2 个采样点的尖刺"，
于是"噪声特征"与"滤波器能力"**在同一组数据上对上了**：
这不是"调参调出来的稳定"，而是**先量出噪声时宽、再据此选滤波长度**的闭环设计。
（异常点集中在跳变沿这一条，同时也解释了案例 7.5 的"温漂"为何只影响正弦的过中占比。）

## 10. 答辩讲述要点（30 秒版）

> "我们把测量链路里所有'看起来玄学'的问题都做成了闭环实验：**数据不对 → 不猜、先建模 → 用'错误变体'复现硬件数字 → 命中即根因**。
> 比如自研 FFT 的最后一个 bug，是我们用'读前一地址'的假设在两组频率上**逐字复现**了硬件的错误读数，才锁定 BRAM 2 拍延迟。
> 而最后一个 bug（案例 8）更值得讲：**它是被'两个不同信号跑出完全相同频谱'这件不可能的事**揪出来的——
> 方波和正弦的 SF/S2/S3 逐字相同，说明输入在进 FFT 之前就被改形了，
> 于是我们查到 ADC 的偏移二进制被当成补码用，在 128 处劈出断崖、凭空造出谐波。
> 这个 bug 只有把激励从方波换成正弦才会暴露——**'仿真通过'只在'激励和现场一样'时才等于'硬件正确'**。
> 这些过程沉淀成了 38 条技能包——这也是我们把这套系统称作'可复现的工程'而不是'能跑的 demo'的原因。"
