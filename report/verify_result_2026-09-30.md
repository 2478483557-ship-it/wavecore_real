## 4. ⚠️ 发现的问题：自研通路在非整数 bin 上报出假峰

### 4.1 现象
1kHz **正弦**时读出 `S2=0001171Hz`。正弦只有一个谱分量，本应是 `S2=0`。

### 4.2 定位过程（同一时刻，两条通路做对照）

| 通路 | 加窗 | 1kHz 正弦的读数 |
|---|---|---|
| IP 通路（`fft_demo.v`，例化 `hann_rom u_hann`） | **Hann 窗** | `S=0001001`，**没有 `A=` 行** → 单峰 |
| 自研通路（`self_fft_1024.v`） | **无窗（矩形窗）** | `SF=976` **+ `S2=1171`** → 两个峰 |

同一个信号、同一个瞬间，**两条通路的结论不一致** → 多出来的那个峰是自研通路自己造的。
`grep -i hann src/self_fft_1024.v` 只有一句注释命中：**该模块从未例化任何窗 ROM**。

### 4.3 定量验算（与实测分毫不差）

fs = 50 kHz，N = 1024 → Δf = 48.8281 Hz/bin。
1000 Hz → `1000 / 48.8281 = ` **bin 20.480（非整数）**，主峰落在 bin20，相对幅度 0.662。

矩形窗的 Dirichlet 核在 bin24（离主峰 4 bin）处：

| 量 | 值 |
|---|---|
| bin24 泄漏幅度（相对满幅） | 0.0903 |
| 占主峰比例 | 0.0903 / 0.662 = **13.6%** |
| 幅度门限 `主峰 >> 3` | **12.5%** |
| 判定 | **13.6% > 12.5% → 越过门限，被报成"第二峰"** |
| 反算实测读数 | `1171 / 48.8281 = 24.0` → **正是 bin24** ✔ |

最坏相位（小数部分 = 0.5）时泄漏可达 **14.3%**，因此在 GAP=4 下
假峰是**结构性、时有时无**的（约 65% 的输入频率会触发），不是偶发干扰。

### 4.4 为什么仿真完全没抓到（重要教训）

`sim/fft_check/gen_tables.py` 第 8 行写着：

> `1024 点 / k 个周期 -> 谱线正好落在第 k 根 bin, 无泄漏。`

仿真的激励是"**1024 点正好 k 个整周期**"，谱线**精确落在整数 bin**，
矩形窗在该处的泄漏**恰好为 0** → 假峰在仿真里**永远不可能出现**。
换成真实板子的 1000 Hz（bin 20.48）就立刻暴露。

> ★ **这是本项目第二次"仿真通过 ≠ 硬件正确"**（第一次是"只测方波，把偏移二进制 bug 放过了"）。
> **通用结论：验证 FFT/窗函数类设计时，激励必须覆盖"非整数 bin"（频率不是 fs/N 整数倍）。
> 只用整周期激励，窗泄漏类问题在仿真里是隐形的。**

### 4.5 修复（已实施）

`src/self_fft_1024.v`：`localparam GAP = 10'd4;` → **`10'd6`**

| GAP | 第一个合格 bin | 泄漏（小数 0.48） | 泄漏（最坏小数 0.5） | 判定 |
|---|---|---|---|---|
| 4（原） | bin24 | 13.6% | 14.3% | ❌ 越线 |
| **6（新）** | bin26 | **8.7%** | **9.1%** | ✅ 稳定低于 12.5% |
| 8 | bin28 | 6.4% | 6.7% | ✅ 更保守 |

**对真实谱峰零副作用**（已核）：

| 真实谱峰 | bin | 离基波(bin20) | 与 GAP=6 比较 |
|---|---|---|---|
| 1kHz 方波 3 次谐波 | bin61 | 41 bin | 41 ≫ 6 ✔ |
| 1kHz 方波 5 次谐波 | bin102 | 82 bin | 82 ≫ 6 ✔ |
| 仿真双音 20/100 周期 | bin20 / bin100 | 80 bin | 80 ≫ 6 ✔ |
| 仿真双音 20/22 周期 | bin20 / bin21 | 1 bin | 原本就该分不开 ✔ |

**现有四场景仿真结果全部不变**（它们的间隔都远大于 6 或本来就 <4）。

**板级复验（第 2 轮，已通过）**：

```
修复前  正弦: SF=0000976Hz  S2=0001171Hz  S3=0000000Hz     <-- 假峰
修复后  正弦: SF=0000976Hz  S2=0000000Hz  S3=0000000Hz     <-- 单峰 ✔

修复前  方波: SF=0000976Hz  S2=0002978Hz  S3=0004980Hz     <-- 真谐波
修复后  方波: SF=0000976Hz  S2=0002978Hz  S3=0004980Hz     <-- 真谐波一根没少 ✔
```

实测值与本文 §4.3 的算术预测**逐项吻合**（bin24 → 预期被压掉；bin61/bin102 → 预期保留）。
其余字段（`V` / `D` / `W` / `TY` / `S` / `A`）两轮**逐字相同**，证明改动无副作用。

## 5. 顺带澄清：`V=1085`（正弦）vs `V=0882`（方波）不是故障

查 `src/board_top.v:187`：

```verilog
wire [7:0] wave_a = (wave_sel_w == 2'd1) ? (rom_addr[7] ? 8'd26 : 8'd230) :   // 方波
                    (wave_sel_w == 2'd2) ? tri_a : sine;
```

| 波形 | 数字幅度 | 数字 Vpp |
|---|---|---|
| 正弦（`sine_256.hex`，取值范围 1~255） | 1 ~ 255 | **254 LSB** |
| 方波（代码写死 `26 / 230`） | 26 / 230 | **204 LSB** |

比值 `204 / 254 = 0.803`；实测 `882 / 1085 = 0.813` —— **吻合（差 1%，在量化/模拟容差内）**。
所以方波天生比正弦小约 20%，**是 RTL 里的设定值，不是故障**。

> 📌 **可选改进（列入待办）**：把方波也改成接近满幅（如 `2 / 253`），
> 让三种波形的 Vpp 一致 —— 对"信号源"这个身份来说更规范。改动是一行常量。

> ⚠️ **绝对值仍以标定为准**：当前 `V=` 用的是**默认 KN=8000（Q10）= 7.8125 mV/LSB，未标定**。
> 换算回去：正弦 1085 mV ÷ 7.8125 = **138.9 LSB**，而数字 Vpp 是 254 LSB ——
> 差值来自 DAC/ADC 各自满量程电压不同，是**固定比例**，正是 `0x8C` 标定要修掉的。
> 所以：**现在可以信"波形之间的比例"，还不能信"绝对毫伏数"** —— 等万用表标定 KN 真值。
