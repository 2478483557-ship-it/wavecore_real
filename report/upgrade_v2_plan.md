# WaveCore 改进方案 v2：往示波器能力靠（2026-09-28）

> 触发：外部评审指出"不算完整示波器：无量程/时基/预触发/连续采集，Vpp 还是 LSB，频谱展示力度不足"。
> 本文给出**逐项可行性判断 + 实现设计 + 分工排期 + 验收标准**。原则：**能用现有硬件做到的必须做，做不到的诚实说不做。**
> 关联：`report/host_gui_review_2026-09-27.md`、`board/uart_protocol.md`、`report/qa_prep.md`

---

## 〇、事实核查（今天最重要的一条）

| 事实 | 出处 | 含义 |
|---|---|---|
| **ADC 采样时钟 ad_clk = 25MHz**（50MHz 二分频），ADC 数据在 sys_clk 下降沿抓取，稳定无跨时钟域 | `src/ad_driver.v` | **ADC 硬件一直在 25MSPS 工作**（AD9280 上限约 28~32MSPS）|
| 波形上传路径 `dcnt == 999` → 每 1000 拍写 1 点 = **50kHz** | `src/wave_frame.v` | 50kHz 是**我们自己抽的** |
| IP-FFT 路径 `parameter DECIM = 1000` → fs = 50MHz/1000 = **50kHz** | `src/fft_demo.v` | 同上 |
| 测量通路（`freq_meter`）直接吃 25MSPS 流（闸门 500_000 拍 = 10ms 计数）| `src/freq_meter.v` | **这就是"测频能到 1MHz、波形却只有 25kHz"的原因** |

**结论**：波形/频谱的可观察带宽瓶颈是**我们自己的抽取比**，不是 ADC、不是串口、不是 BRAM。
→ `fs = 50MHz / DECIM`，DECIM 从 1000 改成 2，**fs 可从 50kHz 提到 25MHz（500 倍）**。

| 档位 | DECIM | fs | 1024 点时间窗 | 4096 点 FFT 分辨率 Δf | 适用 |
|---|---|---|---|---|---|
| T1 | 1000 | 50 kHz | 20.48 ms | 12.2 Hz | 低频高分辨（现状）|
| T2 | 500 | 100 kHz | 10.24 ms | 24.4 Hz | |
| T3 | 200 | 250 kHz | 4.10 ms | 61 Hz | |
| T4 | 100 | 500 kHz | 2.05 ms | 122 Hz | |
| T5 | 50 | 1 MHz | 1.02 ms | 244 Hz | **覆盖测量上限 1MHz** |
| T6 | 20 | 2.5 MHz | 410 µs | 610 Hz | |
| T7 | 10 | 5 MHz | 205 µs | 1.2 kHz | |
| T8 | 4 | 12.5 MHz | 82 µs | 3.1 kHz | |
| T9 | 2 | 25 MHz | 41 µs | 6.1 kHz | 硬件极限（ad_cap 每 2 拍更新）|

> 说明：ad_cap 每 2 个 sys_clk 才更新一次（ad_clk 40ns 周期），所以 **DECIM 最小取 2**（=25MSPS）。
> 串口带宽**完全不变**：波形帧固定 1024 点 ≈ 22 ms/帧。

### 1.2 实现（FPGA，约 100 行改动，风险可控）

| 文件 | 改动 |
|---|---|
| `wave_frame.v` | `dcnt == 999` → `dcnt == decim-1`，`decim` 来自时基寄存器 |
| `fft_demo.v` | `DECIM` 常参 → 寄存器；**频率换算 `peak_bin*50000>>12` 必须同时改为随 fs 变化**（否则读数全错）|
| `self_fft_1024.v` | 同上：`res_freq <= (pk_bin*50000)>>10` → 按当前 fs 计算（需 40 bit 中间量，bin 最大 4095）|
| 新增 `timebase.v` | 8 档 fs 选择器 + 每档的 fs 常量（供 Hz 换算），复位默认 T1（**上电行为与现在完全一致**）|
| `cmd_decoder.v` | 新增 **`0x8D` 设置时基档位**（1B: 0~8）〔`0x8C` 已被电压标定占用〕|
| `board_top.v` | 连线 |

### 1.3 风险与前置实验（必做）

| 风险 | 说明 | 对策 |
|---|---|---|
| **模拟链路带宽未知** ⚠️ | DDS(50MSPS 阶梯)→AD9708→模块滤波/运放→AD9280，真正能通过的信号带宽要实测 | **先跑 `host/link_response_scan.py` 频响实验**（今天就能做，零风险），用曲线决定"最高可用 fs" |
| 无抗混叠滤波 | fs 越低混叠越严重；提高 fs 反而更安全 | 高频演示只在 fs ≥ 2×信号频率时做，并在界面标注当前 fs |
| 时序/资源 | LUT 攻坚前 95.5%、现 24.6% | 本项只改参数与分频，几乎不加 LUT；`0x8D` 只加一个小状态 |
| 回归风险 | 改坏了会毁掉已固化的可用版本 | 改动逐个上板验证；**保持 Flash 里的旧版可用**，新版验证通过再固化 |

### 1.4 验收标准
- 各档设 1kHz 方波：波形图周期数 = `fs×20.48ms/1000`（T1 看到 20 个周期，T5 看到 1 个周期），**逐档目视对数**
- T5（1MHz）下测 1MHz 方波：波形清楚、`S=` 行 ≈ 1MHz/Δf 位置正确
- 上电不改档时行为与 v1.15 **完全一致**（回归零风险）

## 二、电压校准（mV）— P0 ✅ 已实现（2026-09-30）

### 2.1 现状与目标
- 原来：`V=134`（ADC 计数，0~255）→ 外行看不懂，评委质疑"没有电压校准"
- 现在：**`V=1085`（毫伏，4 位）**，协议升 **v1.17**，上位机显示 `1085 mV`

### 2.2 实现（已落地，源码可查）
- FPGA：`src/vpp_mv.v` —— `mV = Vpp_LSB × KN ÷ 1024`，饱和到 9999；
  `KN` 是 Q10 定标的"每 LSB 多少 mV"，由新增命令 **`0x8C`** 写入，上电默认 8000（7.8125 mV/LSB，按 AD9280 0~2V 量程）
- 上报帧：`V=` 字段 3 位 → **4 位**，测量行 19 → 20 字节，整帧 45 → **46 字节**
- 上位机：`host/protocol.py` 正则 `V=(\d{4})`、字段名 `vpp_lsb` → **`vpp_mv`**；GUI 新增"电压标定"一行（应用/原始LSB/恢复默认）
- 回归：`bash sim/mv_check/run_mv_check.sh`（vpp_mv 单元 + 46 字节整帧 + 0x8C 命令解析）

### 2.3 两个关键设计决定（答辩可讲）
1. **没有"零点偏置"项 —— 是刻意去掉的。**
   Vpp 是"最大值−最小值"，是**差分(峰峰值)量**；信号整体平移时 max 与 min 同时动，相减抵消。
   所以 Vpp 换算只有增益 KN 一个待标定量。硬塞一个偏置进去减，等于把无关的直流分量当误差扣掉，
   会**系统性做小读数** —— 那是引入错误，不是校准。（做 Vmax/Vmin 这类绝对值时才需要偏置项。）
2. **没有新增独立行 `MV=`，而是就地改 `V=` 的语义。**
   原计划（见下）是"新增 MV= 行以兼容旧上位机"。实际改为就地替换，理由：
   - 旧字段只有 3 位（≤999），本身已经装不下 mV，**不是"兼容"而是"迟早要改"**；
   - 两个字段并存会出现"屏幕上显示一个、CSV 里记另一个"的经典不一致 bug；
   - 上位机是我们自己的（9/20 已定"演示统一走 PC 上位机"），**在演示冻结前做一次性破坏性变更**成本最低；
   - 正则改一处、字段名改一处，并有协议自检兜底（`python host/protocol.py`）。

### 2.4 标定方法（按优先级）

| 方法 | 需要 | 精度 | 何时做 |
|---|---|---|---|
| **A. 万用表一点定标（首选）** | 万用表 | 好 | **现在就能做**：发 `0x8C 原始LSB`（KN=1024）读原始计数 N → 万用表量真实峰峰值 V_true → 发 `KN=round(V_true×1024/N)` |
| B. 理论推算 + 自环回 | 无 | 中 | 由 DA 输出幅度与实测码值差反推，**标注"待仪器复核"** |
| C. 外部信号源/示波器正式标定 | 仪器 | 高 | 11 月（终验）|

### 2.5 剩余
- **量程**：模拟衰减需要改板（分压/继电器）→ **不做**，只做"满量程刻度 + 输入范围标注"
- **标定值不落 Flash**：复位回默认。若要固化，改 `src/cmd_decoder.v` 的 `KN_DEF`
- 界面小字（`分辨率 xx mV/LSB ｜ 输入范围 0~2V`）待补 —— 目前只在"电压标定"行用文字显示当前 KN

## 三、预触发（pre-trigger）— P1

- **现状**：触发后写指针归零，帧首点 = 触发点（无预触发）
- **改法**：1024 深**环形缓冲**常写；触发到来时记录触发地址，再写 N 点后停 → 从 `触发地址 − 预触发点数` 开始读出
- **预触发比例**：0% / 25% / 50% / 75%
- ⚠️ **命令号改用 `0x8D`**：`0x8C` 已被"电压标定"占用（2026-09-30）。改协议前先查 `board/uart_protocol.md` §6 避免撞号。
- **成本**：`wave_frame.v` 约 40~60 行（地址偏移 + 读地址生成），零 BRAM 增量
- **验收**：设 50% 预触发，请求波形 → 图上能看到触发边沿**左侧**的半个波形，且触发点位置与设定一致
- **演示价值**：高（"能看到触发前发生了什么"是示波器的标志性能力）

## 四、连续采集 — P0（上位机侧，成本最低）

- FPGA 侧本来就在持续写环形缓冲，`0x83` 可反复请求 → **连续采集 = 上位机定时自动请求**
- 上限：1024B/帧 ÷ 460800bps ≈ **22 ms/帧 → 理论上限 ~45 帧/s**；实用 10~20 帧/s 流畅
- 队友1：加"**自动刷新（2s / 1s / 500ms）**"勾选框（已在 `teammate1_task.md` v1.2 的 P0）
- **验收**：勾选后波形图持续刷新，无卡顿、无丢帧（状态栏显示帧率）

## 五、频谱图 / 瀑布图 — P0，**分工：FPGA 出数据 + 上位机画图**

### 5.1 问题定性（回答"这是队友的活还是我的"）
现在 FPGA **只上报 3 个峰值数字**（S/A/SF/S2/S3），所以上位机**画不出频谱图**——**这不是队友的能力问题，是数据源缺失**。
结论：**一半一半** —— ① FPGA 侧增加"幅度谱帧"（**我的活**）② 上位机画柱状图/瀑布图（**队友1 的活**）。

### 5.2 设计：新增 `0x8E` 幅度谱帧（256 点）〔`0x8C` 已给电压标定，勿再占用〕
```
5A A5 02 01 00 + 256 字节(幅度, 8bit 对数压缩) + SUM      ≈ 262 字节 ≈ 5.7 ms @460800
```
- 数据来源：现有 4096 点 FFT 幅度谱 → 每 16 个 bin 取**最大值**（peak envelope）压缩成 256 点
- 8bit 对数压缩：`y = 32*log2(mag+1)` 限幅到 255（动态范围足够看谱）
- 频率轴：`f_k = k × (fs/256)`（fs=50kHz → 每点 195Hz，覆盖 0~25kHz）
- 刷新率：**~10 帧/s**（带宽占用 2.6kB/s，仅占 460800 链路的 6%）
- BRAM 开销：256×8 = 2Kb（用 LUTRAM 或现成 BRAM 余量，几乎不影响 95.5% 的资源）

### 5.3 上位机（队友1）
- **频谱柱状图**：256 根柱、x 轴 Hz（按当前 fs 标注）、y 轴 dB
- **瀑布图**：把每帧 256 点按时间堆叠成热力图（x=频率，y=时间，颜色=幅度）→ 扫频时出现**斜线**
- 这样同时解决：外部评审第 3 条（频谱展示不足）+ 演示视频最需要的"王炸画面"

## 六、自研 FFT "三峰"风险 — P1（我改 RTL）

- **问题**：`SF=976 / S2=1025` 是同一主瓣内的相邻 bin（bin20/bin21），不是两个独立峰
- **改法：非极大值抑制（NMS）**——找到第一峰后，屏蔽其 **±3 bin** 范围再找第二峰，再屏蔽再找第三峰
- **改后预期**（1kHz 方波）：`SF=976`（基波主瓣）→ `S2≈2978`（3 次谐波）→ `S3≈4970`（5 次谐波）= **三个真正独立的峰**
- 成本：`self_fft_1024.v` 峰搜索状态机加"屏蔽窗"（约 40~60 行）
- **验收**：三峰两两间隔 > 3 bin；与 IP 通路（S/A）的峰值互相印证
- 顺带收益：`S2/S3` 的 `≥pk_best/8` 门限保留即可，答辩口径从"三条最强谱线"升级为"**三个独立峰（最小间隔 ≥3 bin）**"，无懈可击
