## 三、⭐ 10/07 新增的两个亮点（**务必录进去**）

### A. 预触发四档 —— 视觉最直观

**怎么录**：
```
1. 「预触发」下拉：0% → 点「应用预触发」→ 请求波形 → 截图
2. 改 50% → 应用 → 请求波形 → 截图
3. 改 75% → 应用 → 请求波形 → 截图
```
**镜头**：**触发沿在图上的位置，从最左边 → 正中间 → 3/4 处移动** ✓

**为什么必须录**：这是**外部评审"无预触发"那条意见的直接答复**，
而且它是**一帧截图就能说清**的功能——看的人立刻懂。

### B. 慢边沿触发修复 —— 讲"我们怎么发现问题"

**怎么录**：
```
1. 信号发生器给【正弦 1kHz】→ 上升沿触发 → 请求波形 → 有波形 ✓
（旁白可提：早期版本正弦完全触发不了，我们定位到"边沿判据太苛刻"并修复）
```

**为什么值得录**：它展示的是**"发现 → 定位 → 修复 → 验证"的完整闭环**。
比"从没遇到问题"更能说明工程能力。

### C. 传感器实测（**等器件到货后补录**）

```
1. 接 MAX9814 → 吹口哨 → 频谱出现【单根谱峰】← 最好看
2. 拍手 → 全频段瞬间抬高
3. 接振动模块 → 敲桌子 → 振动冲击谱
```
**旁白**："把传感器接上去，它就从实验仪器变成**设备状态监测 / 声音频谱分析**的终端。"

## 四、拍摄要点（容易被忽略的）

1. **关键数字必须打字幕** —— "频率误差 <1%"、"电压最大偏差 2.8%"、"帧率 21 帧/s"
   （评委看视频时不会暂停算，字幕是你的机会）
2. **实物镜头别省** —— 板子、飞线、传感器、串口线，都值得 3~5 秒特写
3. **上位机界面要放大**到能看清数字（录制时把窗口拉大、字体调大）
4. **每个环节 ≤30 秒** —— 节奏紧一点，宁可剪掉也不要拖
5. **用支架固定手机/相机**，手持抖动很影响观感
6. **一次拍不完没关系** —— 分环节录，后期剪起来更灵活

## 七、⭐ 两个「同框证明」镜头（**强烈建议加**）

> 理由：GPT 评审指出我们「技术深度够，但**证据组织弱**」。
> 下面两个镜头能把「我说我准」变成「**你自己看**」。

### 镜头 A · 信号发生器 vs 本机读数（**精度的一镜证明**）

**摆位**：信号发生器 ＋ 板子 ＋ 屏幕，**在同一画面内**

**动作**（约 30 秒）

```text
发生器依次设 1V / 2V / 4V（1kHz 方波）
每设一次，给屏幕上的 V= 读数一个特写
```

| 发生器 | 屏幕应显示 |
|---|---|
| 1.0 V | 约 1017 mV |
| 2.0 V | 约 1998 mV |
| 4.0 V | 约 3887 mV |

**旁白**：「以信号发生器为基准，1~4V 范围内**最大偏差 2.8%、平均 0.8%**。」

### 镜头 B · 示波器 vs 上位机（**没造假的证明**）

**⚠️ 关键：示波器探头接哪里？**

| 接法 | 能证明什么 | 评价 |
|---|---|---|
| 接**传感器输出** | 只能证明信号存在 | 一般 |
| ⭐ 接 **AD 模块的输入端** | 示波器看到的就是 **FPGA 实际采样的那个信号**，可与屏幕波形逐一对照 | **推荐** |
| ⭐⭐ 接 **DA 输出** | 对比**发出去的**和**采回来的** | **最强** |

**最佳镜头（10~15 秒）**

```text
[示波器]  板内 DDS 输出的 1kHz 方波
[上位机]  采集到的同一波形 ＋ D=50.0% W=500us
两者同框
```
**这一个镜头同时证明三件事**：
1. **DDS 输出正确**（以示波器为基准）
2. **采集通路正确**（波形对得上）
3. **参数计算正确**（占空比、脉宽）

**⚠️ 探头注意**：用 **1×/10× 高阻档**，不要用 50Ω 档（会加载信号）。
