# FFT 频谱分析设计方案（P1 · 2026-09-05）

## 一、目标与验收
1. 能分辨 **1kHz 与 1.1kHz**（相差 100Hz 的两个正弦 = 方案验收点）
2. 显示幅度谱 + 报出主频（复用串口/测量帧）
3. 做 **IP 核 vs 自研** 双实现 + 资源对比表（评分"性能与资源 20%"）

## 二、先算清楚数学（分辨率从哪来）
频率分辨率 Δf = fs / N（fs=送入 FFT 的采样率，N=FFT 点数）

| 采样率 fs | N=1024 Δf | N=2048 Δf | 能分辨的最小频差 |
|---|---|---|---|
| 25MHz(现 ADC) | 24.4kHz | 12.2kHz | ✗ 远不够 |
| 250kHz | 244Hz | 122Hz | 勉强(1k/1.1k 差100Hz) |
| **50kHz** | 49Hz | **24Hz** | ✅ 1024 点即可，2048 更稳 |
| 25kHz | 24Hz | 12Hz | ✅ |

**结论：低频精细谱必须降采样到 ~50kHz 档**（配合加窗减少频谱泄漏）。

## 三、总体架构（复用现有链路）
```
ad_cap(25M 有效) → 降采样器(可编程分频 fs=25M/D)
   → 窗函数(Hann, 乘法查表)
   → 数据缓冲(BRAM 双口, 攒 N 点)
   → FFT 引擎(IP 或自研 Radix-2)
   → 幅度谱 |X[k]| (复模方/开方近似)
   → 峰值搜索 → 主频 + 幅度 → UART/屏
```

## 四、关键模块与分工（B1/B2/B3）
| 子项 | 内容 | 说明 |
|---|---|---|
| B1 | xfft IP 通路（推荐先用 IP 打通全链路） | Vivado IP: FFT 9.1(xfft_0)，N=1024/2048 可配，可先 1024 跑通 |
| B2 | 降采样器 + Hann 窗 + 缓冲 | 我写 RTL（简单），IP 只需 GUI 生成一次 |
| B3 | 幅度与峰值 → 频率显示 | 复用 bin2bcd/measure_report 扩展 |
| B4 | 自研 Radix-2 1024 点（对比用） | 蝶形单元+控制，**重点加分项**，资源/延迟对比表 |

## 五、需要先定的小决策
1. **窗函数**：Hann（旁瓣低，谱泄漏小）——查表 256 点×?，用 BRAM
2. **N**：先 1024（资源小、IP 通用），若 1k/1.1k 分辨不足升 2048
3. **fs 档位**：预设 3 档（250k/50k/25k 由命令或自动选），频谱刷新 ~N/fs（50k/1024≈20ms/帧，可接受）
4. **自研 FFT**：4.1 版定 Radix-2 DIT，复数蝶形，输入定点化（8bit→12bit 加窗）

## 六、风险与对策
- 泄漏：Hann 窗 + 峰值插值(可选 Rife-Vincent，fans963 用过,精度可抄思路)
- 资源：2048 点 IP ≈ LUT 2-3k/BRAM ~3-5 块，35T 充裕；自研更大但可控
- 时间：B1~B3 预计 3~5 天（含联调），B4 自研 5~7 天——排在 P2 彩蛋前
