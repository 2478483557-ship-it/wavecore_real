# 大模型协作记录 · 精选实录（15 例）

> 用途：设计报告 §5「大模型协作记录」的支撑材料（官方要求：含提示词、模型回答与自我纠错轨迹）。
> 边界说明：**人负责**——需求定义、方案取舍、上板验证、最终判断；**模型负责**——起草、变体分析、审查、文档生成。
> 原始流水：`llm_collab_log.md`（早期逐条）＋各日 `session_summary_*.md`（中后期）＋`skill/README.md`（纠错结晶）。

## 协作模式总览

```
需求/现象 → 与模型协作产出方案或代码 → 人上板实测 → 数据对照
        → 不符则进入"错误变体"复现式定位 → 修复 → 回写技能包（SK-xxx）
```

## 精选 15 例

### E01 · 09-02 · 赛题解读与路线规划
- **场景**：首次参赛，需要把"官方选题指南"翻译成可执行的开发路线。
- **提示词（要点）**："根据指南给出：赛道选择建议、里程碑拆分、无仪器条件下的验证路径。"
- **模型贡献**：给出"先通链路再补指标"的分期路线（M1~M6）与风险清单。
- **人的判断**：采纳主体框架，把"无示波器"作为硬约束纳入每阶段验收。
- **结果**：成为全程 `report/progress_log.md` 的骨架。

### E02 · 09-02 · 无示波器条件下的验证策略
- **场景**：没有示波器，如何证明"板子真的出波形了"？
- **模型贡献**：提出"DA→AD 回环 + PC 侧抓图交叉验证"的替代验证法（板端数据 vs Python 独立解析）。
- **人的验证**：后续所有关键读数均以此交叉验证（如 V=140 与 PC 抓图 139 对齐）。
- **纠错轨迹**：早期曾误以为"回环=免检"；后加入"PC 独立审计"才成立。

### E03 · 09-03 · 综合/时序报告解读
- **场景**：第一次看 `utilization` 与 `timing summary`，看不懂 FDRE 超限与 Setup/Hold。
- **模型贡献**：解释四类资源含义；指出"FDRE 超限应改 BRAM 而非加约束"；解释 WNS 的意义。
- **人的动作**：据此完成"大缓存改块 RAM""LUT 超限改 readmemh ROM"两轮优化。
- **结果**：SK-015；LUT 21,775→19,282。

### E04 · 09-03 · DRC BIVC-1 Bank 电压冲突（真实犯错）
- **场景**：`key0` 被误标 LVCMOS33，与同 Bank 的 `sys_clk` 冲突，实现阶段报错。
- **提示词（要点）**："把报错端口按 Bank 归类，对照官方 XDC 给出正确电平。"
- **模型贡献**：快速定位两端口同属 bank34，给出"以官方例程为准"的修正清单。
- **结果**：SK-005；DRC 通过。
- **人机分工**：报错定位=模型；改约束+重跑=人。

### E05 · 09-03 · UART RX 采样时序 bug（命令收不到）
- **场景**：下行命令帧无反应。
- **模型贡献**：逐步推演位时序，指出 v1.0"数据位按半位长采样→采样点落位边界"的错误，给出"起始位中点后每满一位长采一次"的修正。
- **人的验证**：HEX 发 0x81 帧 → LED 正确跳档。
- **结果**：SK-007。

### E06 · 09-05 · 自动双模式测频 + 位宽越界
- **场景**：低频测周法"永远无效"。
- **纠错轨迹**：全精度逐项排查 → 模型参与枚举可能点 → 命中 `24'h1_000000`（2^24 需 25 位）被截断为 0。
- **结果**：SK-013；测周法走通。
- **附**：同轮完成闸门/测周自动切换（10kHz 判据）。

### E07 · 09-16 · 触发采集："归零 + 单写者"
- **场景**：触发帧首点不是边沿（相位随机）。
- **模型贡献**：给出"触发瞬间指针对零再写满一圈"的语义修正；遇到 multi-driven 报错后给"单写者+控制脉冲（fill_rst）"的重构方案。
- **人的验证**：上升沿→帧前 6 点全高；下降沿→全低。
- **结果**：SK-021。

### E08 · 09-16~17 · 三层数字抗噪（正弦 ×2/乱跳）
- **场景**：正弦频率翻倍、乱跳；同频方波完全正常。
- **模型贡献**：提出"连续 2 拍确认 / 施密特迟滞 / 5 点中值滤波"三层组合；并用 Python 20 万组验证中值网络。
- **人的验证**：逐层上板，形成 V: 201→170→140 的三步证据链。
- **结果**：SK-019；正弦全频段读数与 PC 对齐。

### E09 · 09-17 · 单趟流式双峰的三个连环坑
- **场景**：方波第二峰永不输出（双音却正常）。
- **纠错轨迹**：①主峰寄存器晚一拍被存为候选 → ②Hann 旁瓣顶掉真次峰 → ③正解=双端"相隔>2"约束的双最大值级联。
- **模型贡献**：三轮假设+反例分析；人负责逐轮上板对照。
- **结果**：SK-022；S=1001 + A=3003 稳定。

### E10 · 09-19 · case-default 吞掉非阻塞赋值
- **场景**：自研 FFT 状态机"从未前进"（采集正常）。
- **模型贡献**：按 Verilog 语义构建"同块两次赋值 last-write-wins"变体 → 复现现象 → 修复（补空 case）。
- **结果**：SK-023；核心首次跑通。
- **人的反思**：此前手写"理想语义"仿真通过，教训=**按真实语义建模**。

### E11 · 09-19 · 旋转因子表错 + 镜像抢峰
- **场景**：频谱"稳定但错"（1kHz→49kHz）。
- **纠错轨迹**：①金标准改用"读同一份 hex"立刻复现峰值=20（暴露补零表错）②找峰限制正半轴（bin≤511）解决镜像。
- **结果**：SK-024。

### E12 · 09-19 · BRAM 2 拍读延迟（旗舰案例）
- **场景**：数值修复后仍 1kHz→1367Hz（bin28）。
- **模型贡献（关键）**：提出"读 i−1 / 读 i−2"两种错误变体并仿真 → **在 1kHz 与 2kHz 两组数据上逐字复现硬件输出**（[1367,1318,1709]/[2686,3369,8740]）→ 一击定案。
- **修复**：找峰扫描与蝶形读同样等待一拍；地址保持有效，对 1/2 拍延迟均安全。
- **结果**：SK-025；SF/S2/S3=976/1025/2978 与模型逐字一致。

### E13 · 09-20 · 波形识别"怎么调都是 3"
- **场景**：新写的识别器恒输出 3（异常）。
- **纠错轨迹**：先误判"闸门/尖刺"，两轮干扰排查未果；最终模型复核代码假设 → 发现"窗口 2048 点@50kHz"被写成**逐时钟取样**（41µs）。
- **结果**：SK-026；修复后五场景 TY=1/0/2/3/3 全对。
- **人的作用**：坚持"真凶未明不罢休"，避免把误判写进文档。

### E14 · 09-20 · Flash 固化四坑
- **场景**：首次固化断电自启。
- **纠错轨迹**：Add CfgMem 灰（需先 Remove 旧节点）→ `.bit` 不被接受（转 `.mcs`）→"set flash parameters"失败（残留对象脏）→ 目标自动关闭需 reopen。
- **结果**：SK-027 + `board/flash_guide.md`；固化成功。

### E15 · 09-21~今 · "全库审计"协作循环（工程外延）
- **场景**：随产出增多，出现"清单表缺条目/重复条目/状态陈旧"等文档漂移。
- **提示词（要点）**："审计 skill 清单与正文一致性、扫描全库陈旧状态词、输出差异清单后再修复。"
- **模型贡献**：批量扫描+逐条修复（缺失 017~028、删重复 SK-005、三条'待复核'改终验……）。
- **人的作用**：抽查复核（本队实际因用户抽查而修正过一次）。
- **价值**：证明 LLM 协作不仅写代码，也能承担"质量审计"角色。
