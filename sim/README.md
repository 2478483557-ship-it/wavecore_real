| D | 双音 20+100 周期（相隔 80 bin）| `dual20_100.hex` | **集合相等** `{SF,S2}={976,4882}`，`S3=0` | 两个峰都报出来，不指定谁第一 |

为什么 C/D 的判据要这么写（**不是被测设计变差，是原来的判据太脆**）：

- **C**：两个音只隔 2 bin，加 Hann 窗后主瓣糊成一团，bin20/21/22 幅度只差 0.1%，
  峰值 bin 由取整噪声决定 → 判据钉死在 `1002±60` 就会随机翻车。
- **D**：两个音**等幅**，谁排第一本来就是"并列"（数值模型实测只差 0.09%），
  改窗后次序会翻 → 判据必须是"集合相等"，不能指定谁当 SF。

## 波形窗口：怎么找到关键信号（2026-09-27 备忘）

TB 层次：`/tb_cmd_decoder/` 下有实例 **u_tx**（uart_tx）、**u_rx**（uart_rx）、**dut**（cmd_decoder）；`arb_cnt/sf_cnt` 只是 TB 里的计数变量，不是被测信号。

**方法 A（Tcl，最稳）**：在仿真窗口的 Tcl Console 里粘：
```tcl
add_wave {{/tb_cmd_decoder/line}} {{/tb_cmd_decoder/u_rx/cnt}} {{/tb_cmd_decoder/u_rx/state}} {{/tb_cmd_decoder/u_rx/rx_data}} {{/tb_cmd_decoder/u_tx/txd}} {{/tb_cmd_decoder/arb_load}} {{/tb_cmd_decoder/arb_fcw}}
restart
run all
```
**方法 B（GUI）**：左侧 **Scopes** 面板 → 展开 `tb_cmd_decoder` → 点 `u_rx` → 中间 **Objects** 面板里选 `cnt`/`state` → 右键 **Add to Wave Window**。
（若面板不见了：菜单 Window → Scopes / Objects）

**量一位（108 拍）**：波形里找 `line` 上一段"低电平"（起始位）→ 工具条两根竖直光标卡住两端 → 应读 **2160 ns**；同时看 `u_rx/cnt` 从 0 数到 107。

## 读波形：为什么低电平宽度不一样？（2026-09-27 答疑）

串口线上 **低电平 = 0 位**。一个字节里的 0 位有几个、是否连在一起，决定了低电平段的长短——
**连续几个 0（含起始位）会连成一片**，所以宽度是 1 位、2 位、3 位…… 不等。

**铁律：最窄的低电平 = 1 位 = 2160 ns = 108 拍 @50MHz**；其余宽度都是它的整数倍。
（1 位 = 1/460800 s = 2170ns，取整 DIV=108 → 108×20ns = 2160ns）

第一帧 `5A A5 85 00 04 E8 03 00 00 74` 中各段低电平的**预期宽度**（可用作核对答案）：

| 字节 | 低电平段宽度 (ns) |
|---|---|
| 0x5A | 4320, 2160, 2160, 2160 |
| 0xA5 | 2160, 2160, 4320, 2160 |
| 0x85 | 2160, 2160, 8640 |
| 0x00 | 19440（起始位+8个0 连成 9 位）|
| 0x04 | 6480, 10800 |
| 0xE8 | 8640, 2160 |
| 0x03 | 2160, 12960 |
| 0x00 | 19440 |
| 0x00 | 19440 |
| 0x74 | 6480, 2160, 2160 |

- 每个字节固定 10 位 = 21600 ns；字节之间由停止位高电平隔开（≈2160 ns，另加几十 ns 的字节间隙）
- 宽度换算：n 位 → n×2160 ns（2160 / 4320 / 6480 / 8640 / 10800 / 12960 / … / 19440）

**留档要求**：用双光标卡住一段**最窄**的低电平 → 读数应为 **2160 ns** → 截图存 `sim_wave108.png`。
**交叉复核**：同时把 `u_rx/cnt` 拖进波形窗，一个低电平位内它从 0 数到 107（108 拍），一一对应。

## 自动测宽：让 TB 自己报低电平宽度（2026-09-27 新增）

手动拖光标容易差几十~几百 ns（实测偏差示例：真值 6480/8640 ns，手读成 6930/9090 ns —— 两段差值仍恰好是 1 位 2160 ns，但绝对值整体偏大 450 ns）。
**改用自动量**：TB 里加了"低电平拍数统计器"，`restart` → `run all` 后 Console 会逐段打印宽度（只打前 30 段，避免刷屏）：

```
[PULSE] 低电平宽度 = 4320 ns ( 216 拍 )
[PULSE] 低电平宽度 = 2160 ns ( 108 拍 )
...
```

**判据**：所有宽度必须 = **2160 ns 的整数倍**，最窄段 = **2160 ns = 108 拍**。
第一帧的预期序列（23 段）：

| 字节 | 低电平段宽度 (ns) | 折合拍数 |
|---|---|---|
| 0x5A | 4320, 2160, 2160, 2160 | 216,108,108,108 |
| 0xA5 | 2160, 2160, 4320, 2160 | 108×3, 216 |
| 0x85 | 2160, 2160, 8640 | 108,108,432 |
| 0x00 | 19440 | 972（起始位+8 个 0）|
| 0x04 | 6480, 10800 | 324, 540 |
| 0xE8 | 8640, 2160 | 432, 108 |
| 0x03 | 2160, 12960 | 108, 648 |
| 0x00 | 19440 | 972 |
| 0x00 | 19440 | 972 |
| 0x74 | 6480, 2160, 2160 | 324,108,108 |

末尾汇总行：
```
====== 低电平宽度: 共 xx 段, 其中 1 位宽 2160ns/108 拍 xx 段 ======
```

**手动量的正确姿势**（要波形截图时用）：先框选放大到"一个字节占满窗口"（此时 1 位 ≈ 60 像素以上），再把两根光标分别拖到**一段最窄低电平的下降沿和上升沿**，读数应为 2160 ns。

## 第一帧实测时间轴（可逐段核对，2026-09-27）

**推导依据**
- 仿真 0 时刻起：复位 10 拍 + 复位后再等 10 拍 + 启动握手 3 拍 → 第一个起始位下降沿 = **450 ns**
- 字节周期 = 10 位 + 3 拍字节间隙 = 2160×10 + 60 = **21660 ns**（第 n 字节起点 = 450 + 21660×(n-1) ns）

**十个字节的起始时刻**

| 字节 | 0x5A | 0xA5 | 0x85 | 0x00 | 0x04 | 0xE8 | 0x03 | 0x00 | 0x00 | 0x74 |
|---|---|---|---|---|---|---|---|---|---|---|
| 起点 (µs) | 0.45 | 22.11 | 43.77 | 65.43 | 87.09 | 108.75 | 130.41 | 152.07 | 173.73 | 195.39 |

**字节 0x5A 逐段（b0..b7 = 0,1,0,1,1,0,1,0）**

| 段 | 起 → 止 (µs) | 宽度 | 对应位 |
|---|---|---|---|
| 空闲高 | 0 → 0.45 | — | 复位+等待+握手（线路空闲必须为高）|
| 低 ① | 0.45 → 4.77 | 4320 ns = 2 位 | 起始位 + b0=0 连成一片 |
| 高 | 4.77 → 6.93 | 2160 | b1=1 |
| 低 ② | 6.93 → 9.09 | **2160 ns = 1 位 = 108 拍** ★ | b2=0 |
| 高 | 9.09 → 13.41 | 4320 | b3=1, b4=1 |
| 低 ③ | 13.41 → 15.57 | 2160 | b5=0 |
| 高 | 15.57 → 17.73 | 2160 | b6=1 |
| 低 ④ | 17.73 → 19.89 | 2160 | b7=0 |
| 高 | 19.89 → 22.05 | 2160 | 停止位 |
| 间隔 | 22.05 → 22.11 | 60 ns = 3 拍 | 字节间空隙 |

**交叉验证**：`[TB] arb_load!` 打印时刻 215970 ns，反推第 10 字节起点 = 195390 ns（= 450 + 21660×9）✓；
仿真实测读数 0.45 / 4.77 / 6.93 / 9.09 µs 与理论逐项吻合 ✓

**读数据规范（教训）**：报测量结果时必须写清"**起止时刻**"还是"**宽度**"——
本次曾因把"6.93~9.09（起止时刻）"误读成"两段宽度"，得出"偏 450 ns"的错误结论。
